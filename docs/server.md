# Сервер и сеть

## Сервер

`marshal.py`, Python 3.7+, без единого pip-пакета.

| Файл | Что это |
|---|---|
| `marshal.py` | сервер: вебсокет-хаб, REST, API, обе панели |
| `panel.html` | панель маршала |
| `admin.html` | админка, за паролем |
| `marshal.conf` | настройки и пароли. **Не в репозитории**, создаётся при первом запуске |
| `karts.conf` | **номера и лимиты картов по DUUID, при обновлении не заменяется.** Не в репозитории |
| `rides-state.json` | идущие заезды: переживают перезапуск сервера. Пишется сам, не в репозитории |
| `fakekart.py` | поддельные карты для проверки без железа |
| `logs/` | логи по часам |

### Первый запуск

`python marshal.py` или `Картинг.bat`. Сервер создаст `marshal.conf`:

- пароль админки генерируется **случайно** — строка `admin_pass`;
- пароль панели маршала `marshal_pass` пустой: вход без пароля, удобно для
  кассы за стойкой;
- `api_token` не задан — внешний API выключен.

Пароли меняются только в `marshal.conf`. Остальное правится из админки, сервер
сам перепишет файл и применит без перезапуска.

### Основные настройки `marshal.conf`

| Строка | Что задаёт |
|---|---|
| `port`, `host` | где слушать. По умолчанию `8080` на всех адресах |
| `presets` | кнопки длительности заезда, минуты через запятую |
| `test_presets` | кнопки тест-драйва |
| `speeds` | градации скорости `подпись:значение`, значение 0..100 |
| `speed_crawl`, `crawl_seconds` | лимит и длительность докатки |
| `crawl_mode` | `restart` — докатка через перезапуск поездки, `live` — без |
| `drive_on`, `drive_off` | HTTP-команды разрешения движения, по умолчанию `On6` / `Off6` |
| `speed_http` | дублировать лимит по HTTP после вебсокета |
| `status_period` | как часто спрашивать телеметрию, секунды, не меньше 2 |
| `kart_user`, `kart_pass` | вход в веб-морду карта, нужен админке |
| `api_token` | токен внешнего API. Пусто — API выключен |
| `http.<DUUID>` | адрес карта для HTTP вручную, если карт за NAT и до него проброшен порт. Главнее адреса из телеметрии |
| `syslog_port`, `syslog_from` | принимать журнал роутера по syslog на этот UDP-порт (обычно 514) и только с этих адресов (по умолчанию `192.168.1.1`). `0` — не слушать. Строки роутера идут в лог с пометкой `RT` |

### Переподключение карта

Пока вернувшийся карт ни разу не ответил на `Status` по новому соединению,
сервер не шлёт ему HTTP. Исключение одно: если последняя известная
телеметрия говорит `kOn=1`, разрешение движения снимается сразу. Подсветка
(`On7`) и сверка разрешения уходят по первому ответу, и не из потока, который
читает вебсокет карта.

По логам 25–28.10 `On7`, ушедший до первого ответа, давал повторный обрыв в
27 случаях из 84, после первого ответа — 0 из 35. Здоровая плата отвечает за
0,1 с, так что подсветка всё равно загорается почти сразу.

### Реестр желаемого состояния

Сервер **не выполняет команды.** Он помнит, каким карт должен быть, и
приводит его к этому. Три поля, все видны в телеметрии:

| Желаемое | Подтверждается |
|---|---|
| `gate` — разрешение движения | `kOn` |
| `speed` — лимит в процентах | ответом платы |
| `light` — выход 7 | `kOn1` |

Фоновый цикл раз в две секунды сверяет и, если расходится, шлёт **ровно одну
команду на карт**.

- не дошло — не потеряно, дошлётся при возврате
- уже стоит нужное — запрос не уходит вовсе
- пачек не бывает по построению

Это главное архитектурное решение проекта. Оно убрало рванность хода и
превратило тысячу переподключений в ноль запросов.

### Фазы заезда

| Фаза | gate | speed | light |
|---|---|---|---|
| свободен | 0 | — | 1 |
| заезд | 1 | лимит карта | 1 |
| докатка | 1 | лимит докатки | 0 |
| конец | 0 | — | 1 |

**Докатка** — после оплаченного времени карт ещё едет на пониженной скорости
с погашенной подсветкой. Это сигнал клиенту, что пора в бокс.

Лимит докатки можно задать **на каждый карт отдельно** в админке: контроллеры
откалиброваны по-разному, и один и тот же процент на разных картах даёт
разную скорость.

### Опознание картов

Карт опознаётся по **DUUID** — номеру чипа, а не по IP. Номер на кузове и
лимиты хранятся в `karts.conf` строками `<DUUID> = номер`,
`<DUUID>.speed = лимит`, `<DUUID>.crawl = лимит докатки`. IP сервер берёт из
телеметрии карта и нужен ему только для HTTP-команд.

### Логи

`logs/marshal-ГГГГ-ММ-ДД_ЧЧ.log`, новый файл каждый час, метка времени с
миллисекундами. Чистятся сами: не старше 7 дней и не больше 100 МБ всего.

Каждый обрыв пишется с причиной и временем тишины перед ним:

```
WS sys 12803939  карт отключился — плата закрыла соединение | на связи 312 с, последний кадр 9.4 с назад
```

| Причина | Что значит |
|---|---|
| `плата закрыла соединение` | плата сама закрыла сокет — решение её прошивки |
| `плата закрыла вебсокет (close N)` | то же, но по правилам вебсокета, с кодом |
| `соединение сброшено со стороны платы (WinError 10054)` | сброс с той стороны: обычно плата переподключила Wi-Fi |
| `Windows оборвала соединение сама (WinError 10053)` | плата перестала подтверждать данные или у кассы пропала сеть |
| `мусор …`, `битые байты …`, `кадр длиной …` | поток сбился: плата прислала обрезанный кадр |

## Сеть площадки

```
Провайдер
   └── MikroTik 192.168.88.0/24    ← сеть ТЦ, НЕ СБРАСЫВАТЬ
         └── Keenetic Skipper 4G KN-2910
               порт 0 (синий) = WAN, 192.168.88.48
               порты 1, 2, 3 = LAN
               LAN 192.168.1.1/24, Wi-Fi площадки
                     ├── карты 192.168.1.x
                     └── кассовый ПК 192.168.1.50 — сервер
```

### Настройки Keenetic, которые обязательны

| Параметр | Значение | Почему |
|---|---|---|
| Канал | **1 вручную**, не авто | автовыбор переезжает и роняет всех разом |
| Ширина канала | **20 МГц** | 40 МГц в забитом ТЦ собирает помехи |
| Диапазон | только 2,4 ГГц | ESP8266 не видит 5 ГГц |
| Шифрование | WPA2-PSK | в WPA3 платы не заходят |
| **802.11 r / k / v** | **выключить** | роутер сам выгонял клиентов |
| Band Steering | выключить | |
| Изоляция клиентов | выключить | иначе карты не увидят сервер |
| Резервации | по MAC на каждый карт | иначе адреса пляшут |
| **Резервация кассы** | `192.168.1.50` за MAC кассы | адрес зашит в прошивку всех картов |

**802.11k/v — главный виновник обрывов.** Роутер сам просит клиента
отключиться и уйти на другую точку, а другой точки нет. В журнале роутера
это строки `deauthenticated by AP (reason: due to BSS transition management)`.
После выключения обрывы упали с 1129 за два часа до 34 за три дня.

Что будет при сбросе роутера и смене адреса кассы — в
[безопасности](bezopasnost.md#сброс-роутера).
