# Маршал (`marshal.py`): как работает сервер картов

Сервер картов клуба: держит связь с платами, ведёт заезды, показывает панель
маршала и админку, отвечает CRM. Описана версия **8790002** (25.11.2026 20:13,
PR #20 защита, #21 продление без Stop и скорость по градациям, #22 перевзвод
после щелчка I/O). По записям агента на кассе это и есть версия, которая
работает на кассе (ветка `kassa-sync-reconnect`).

**Как читать метки.** Утверждения о поведении маршала **без метки** прочитаны в
коде `marshal.py`, `panel.html`, `admin.html` этой версии: это факт о программе.
Метки стоят на утверждениях о платах, картах, кассе и сети:

- **[измерено]** — видно в журналах или замерено, с датой;
- **[владелец]** — со слов владельца;
- **[разбор прошивки]** — из разбора кода прошивки (`ai/03-proshivka.md`), на картах
  не проверялось;
- **[не проверено]** — догадка или открытый вопрос.

Связанные файлы базы: общая картина — `ai/00-sistema.md`; правила безопасности —
`ai/01-bezopasnost.md`; плата изнутри — `ai/03-proshivka.md`; сеть — `ai/05-set.md`;
процедуры (выкатка, USB-лог, живые поля) — `ai/06-instrumenty.md`; нормы
телеметрии — `ai/07-izmereniya.md`; симптом → действие — `ai/08-diagnostika.md`;
карты по номерам и DUUID — `ai/09-karty.md`; журналы и поиск — `ai/10-zhurnaly.md`;
открытые вопросы — `ai/11-otkrytye-voprosy.md`.

## 0. Самое важное (прочитать первым)

1. **`kOn` — единственный настоящий тормоз.** При `kOn=1` карт едет от педали,
   что бы ни показывали `driveOn` и лимит [измерено 10.09]. Свободный карт маршал
   держит разоружённым (`/Off6`, `kOn=0`).
2. **Маршал не «выполняет команды», а помнит, каким карт должен быть**
   (реле, лимит, выход 7), и досылает недошедшее, когда плата вернётся.
3. **Заезд идёт кусками по 540 с** и продлевается за 8 с до конца куска. Причина —
   плата после `Start` ждёт включения I/O и через 600 с ожидания сама снимает
   реле [разбор прошивки; измерено на №15 25.11].
4. **Продление обычно бесшовное** (один `Start`, реле не падает). Через `Stop`
   (свет и реле гаснут ~2 с, контроллер перезагружается) — только если плата
   уже «считает заезд сама» (гость щёлкнул I/O) или не подтвердила продление.
5. **Защита:** `255` в `adcIn`/`adc0`/`adc3` при включённом реле — маршал сам
   закрывает заезд и 10 минут не даёт стартовать на этом карте.
6. **Маршал запускает `fdcrm.exe`.** Закрытие окна CRM гасит маршал и все
   процессы клуба. Отдельно маршал не запускать (решение владельца).
7. **Перезапуск маршала — только между группами:** убить по PID процесс
   `python.exe` с `marshal\marshal.py` в командной строке, `fdcrm` поднимет его
   через ~2 с (`ai/06-instrumenty.md`, раздел 7). Идущие заезды переживают
   перезапуск (`rides-state.json`), но все карты 2–3 с без связи.
8. **Секреты не показывать:** `admin_pass`, `marshal_pass`, `api_token`,
   `kart_pass`, пароль Wi-Fi. Значения — только в закрытом репозитории
   FireDrift_Access (`dostupy.md`).

### 1.2. Процессы

| Процесс | Что делает | Адрес |
|---|---|---|
| `fdcrm.exe` | окно CRM, надзор за остальными | — |
| `python.exe …\marshal\marshal.py` | маршал | `0.0.0.0:8080` (карты, панель, админка, API) |
| `crmd` | служба CRM | `127.0.0.1:8095` |
| `node.exe` | узел игровых ПК | `0.0.0.0:8090` |
| `bridge\clubbridge.exe` | мост CRM ↔ маршал | ходит на `127.0.0.1:8080` |

- `fdcrm` поднимает упавший маршал примерно через 2 с [измерено 25.11 при
  выкатке #20–#22]. После 5 падений подряд, по записям кассы, сдаётся
  [не проверено]: если новая версия падает при запуске, маршал останется лежать.
- **Закрытие окна CRM гасит все процессы клуба**, маршал тоже.
- **Решение владельца, не пересматривать:** CRM и маршал связаны, запуск маршала
  отдельно от CRM не предлагать.
- Касса выключается через «Завершение работы» (база CRM на SQLite с WAL), днём
  без нужды не перезагружается: каждая перезагрузка — 20–90 с без связи у всех
  картов [измерено 23–24.11].

### 1.3. Что происходит с картами, когда маршала нет

Вебсокет рвётся у всех картов сразу. Дальше плата живёт сама
[разбор прошивки, `ai/03-proshivka.md`]:

- **Карт в заезде** едет дальше по своему таймеру: реле держится до 600 с от
  последнего `Start` (или `Length` + 60 с парковки, если гость щёлкал I/O).
  Затем плата сама снимает реле — карт встаёт посреди трассы.
- **Свободный карт** включает **местный режим**: зажигает подсветку и по щелчку
  I/O едет 600 с без оплаты, потом минуту на 20%.
- Маршал вернулся: заезды поднимаются из `rides-state.json`, вернувшиеся карты
  получают их обратно (раздел 3.7), местное катание у свободного карта защита
  останавливает (раздел 5).

### 1.4. Как убедиться, что маршал жив

Короткими командами PowerShell на кассе:

```powershell
curl.exe -s --noproxy "*" http://127.0.0.1:8080/health
```

Должно быть `{"ok": true, "karts": N}`, где N — сколько плат сейчас подключено.

```powershell
Get-CimInstance Win32_Process -Filter "Name='python.exe'" | Where-Object { $_.CommandLine -like '*marshal.py*' } | Select-Object ProcessId, CreationDate
```

`CreationDate` — когда маршал запущен последний раз. Если время свежее, а
никто не перезапускал, — маршал падал и `fdcrm` его поднял: искать причину в
конце предыдущего часового лога (`ai/10-zhurnaly.md`).

### 1.5. Ярлыки `.bat` из репозитория

`Картинг.bat`, `Сервер.bat`, `Стоп.bat`, `Лог.bat`, `Автозапуск.bat` сделаны для
установки **без CRM**: `Картинг.bat` запускает `Сервер.bat` (цикл «упал —
поднять через 5 с»), `Стоп.bat` убивает процесс на порту 8080, `Автозапуск.bat`
кладёт ярлык в автозагрузку Windows.

**На кассе маршал поднимает `fdcrm`.** Поэтому там:

- `Картинг.bat`, `Сервер.bat`, `Автозапуск.bat` не запускать: получится второй
  маршал, который будет драться с первым за порт 8080;
- `Стоп.bat` не останавливает маршал, а перезапускает его (`fdcrm` поднимет
  через ~2 с) — это тот же перезапуск, со всеми его правилами;
- `Лог.bat` безопасен: только показывает хвост свежего лога. Но он держится за
  тот файл, который был свежим при запуске; в новом часе его надо запустить
  заново.

Есть ли эти ярлыки в `C:\FireDrift-тест\marshal\` — **[не проверено]**.

### 1.6. Что крутится внутри `marshal.py`

| Поток | Как часто | Что делает | Функция |
|---|---|---|---|
| веб-сервер | по запросу | панель, админка, API, приём вебсокетов картов | `Handler`, `handle_ws` |
| заезды | раз в 1 с | продления, перевзвод, докатка, конец заезда, сторож свободного карта, запись `rides-state.json` | `ride_ticker` |
| желаемое состояние | раз в 2 с | досылает реле, лимит, выход 7 | `want_loop` |
| опрос | непрерывно | `Status` каждому карту по очереди | `status_poller` |
| журнал роутера | по пакету | приём syslog, если `syslog_port` не 0 | `syslog_listener` |
| запись лога | фоном | строки в `logs\` и в вывод | `_Tee._writer` |

Нужен только Python 3.7+, без пакетов. Лог пишется отдельным потоком через
очередь в памяти: если OneDrive или консоль задерживают запись, маршал не
встаёт (06.09 так замерзал 20 раз за смену). Клик мышью в окно консоли больше
не морозит процесс: режим выделения выключается при запуске.

## 2. Связь с картами

### 2.1. Три канала

| Канал | Кто звонит | Что идёт |
|---|---|---|
| вебсокет на `192.168.1.50:8080` | **плата** сама звонит маршалу | команды `Start`, `Stop`, `Status`; ответы и телеметрия |
| HTTP на порт 80 платы | маршал → плата | `/On6`, `/Off6`, `/On7`, `/Off7`, `/maxSpeed?maxSpeed=N` |
| вебсокет на порт 81 платы | браузер → плата | веб-морда платы; маршал им не пользуется |

- Адрес `192.168.1.50:8080` зашит в прошивку платы [разбор прошивки]. Порт 8080 в
  `marshal.conf` менять нельзя: карты всё равно звонят на 8080.
- Карт опознаётся по **DUUID** — номеру чипа ESP8266 (последние 3 байта MAC в
  десятичном виде), а не по IP. DUUID приходит в первом же JSON от платы (`Init`
  или `Status`). До опознания карт числится под своим IP и в панели не
  показывается 15 с.
- IP платы маршал берёт из её телеметрии (поле `ip`). Строка
  `http.<DUUID> = адрес:порт` в `marshal.conf` его перебивает (для карта за NAT).

### 2.2. Опрос телеметрии

Маршал шлёт `{"Command": "Status"}` каждому карту по очереди, размазывая опрос
по `status_period` (6 с): при 12 картах между запросами ~0,5 с. События короче
6 с можно не увидеть. Плата отвечает JSON-строкой телеметрии и `Status OK`.

В лог идёт не весь JSON (~700 символов), а выжимка полей в постоянном порядке:
`driveOn Speed lengthDrive timeDriveOn remoteMode localModeStart
localModeWaitStart localModeDriveON blockLokalDrive localDrivesCount DrivePoints
timeParking kOn kOn1 adcIn adc0 adc3 aIn dIn rssi reboots uptime`. Полная
телеметрия видна только в админке («Живые поля»). Что значит каждое поле —
`ai/07-izmereniya.md`.

### 2.3. HTTP к плате: строго по одному

- Плата обслуживает HTTP и вебсокет в одном цикле: пока она разбирает HTTP,
  вебсокет стоит [разбор прошивки]. Поэтому маршал шлёт **один HTTP-запрос на
  весь парк за раз** и делает паузу 0,8 с между запросами к разным платам
  (`http_parallel = 1`).
- Таймаут запроса — `drive_timeout` (3 с). Запросы из админки — 8 с.
- Каждый запрос идёт с заводским логином веб-морды (`kart_user`/`kart_pass`) и
  мимо системного прокси.
- **Отставка.** Два неудачных запроса подряд — плата 20 с не получает HTTP
  совсем, чтобы мёртвая плата не держала общую очередь. Отставка снимается
  сразу, как только плата снова подключилась.

### 2.4. Желаемое состояние

Маршал хранит для каждого карта, каким он должен быть:

| Поле | Что | Подтверждается |
|---|---|---|
| `gate` | реле разрешения движения (`/On6`/`/Off6`) | `kOn` в телеметрии |
| `speed` | лимит, проценты (`/maxSpeed`) | успешным ответом платы на HTTP |
| `light` | выход 7, подсветка (`/On7`/`/Off7`) | `kOn1` в телеметрии |

Цикл раз в 2 с сверяет желаемое с телеметрией и шлёт **одну команду на карт**:
сначала реле, потом лимит, потом свет.

- Уже стоит нужное — запрос не уходит.
- Карт не на связи или в отставке — команда ждёт и уходит, когда он вернётся.
- Карт только что переподключился и ещё ни разу не ответил на `Status` — тоже
  ждёт.
- Паузы между досылками: 3, 8, 20, 40 с. После 4 досылок маршал сдаётся и пишет
  `СДАЮСЬ: <разрешение движения|лимит|выход 7> не подтвердилось за 4 попыток —
  смотри плату`. Это признак проблемы с самой платой, а не с одной командой.

Лимит по полю `Speed` не сверяется: во время заезда оно показывает не то, что
задано (после `Start` встаёт на 100 и не меняется) [измерено 12.09].

### 2.5. Обрыв и возвращение карта

**Обрыв.** Маршал пишет причину и время тишины:
`карт отключился — <причина> | на связи N с, последний кадр N с назад`
(таблица причин — `ai/10-zhurnaly.md`). От карта остаётся **слепок**: имя, заезд,
последняя телеметрия. Панель рисует по нему карточку «нет связи» с идущим
таймером. Слепок без заезда держится 10 минут, с заездом — пока заезд не кончится.

**Кадры-мусор.** Кадр длиннее 64 КБ, мусорный заголовок, битый UTF-8 в
текстовом кадре — маршал закрывает соединение с причиной (`мусор …`, `битые
байты …`, `кадр длиной …`). Раньше такой кадр ронял поток с `MemoryError`
[измерено 26.10]. Плата всё равно переподключится сама.

**Возвращение свободного карта.** HTTP не уходит, пока плата не ответила на
первый `Status` по новому соединению: `/On7` до первого ответа давал повторный
обрыв в 27 случаях из 84, после — 0 из 35 [измерено 25–28.10]. Исключение: если
в последней известной телеметрии `kOn=1`, `/Off6` уходит сразу, в отдельном
потоке. По первому ответу маршал приводит свободный карт к виду «реле выключено,
свет горит».

**Возвращение карта посреди заезда** — раздел 3.7.

## 3. Заезд от старта до конца

### 3.1. Старт

Кнопка в панели или `/api/v1/start` из CRM → `ride_start`:

1. Заезд **сразу** записывается на сервере: фаза `ride`, оплачено до
   `t_paid = старт + минуты`, конец с докаткой `t_end = t_paid + crawl_seconds`.
2. **Реле:** `/On6`. Если телеметрия уже показывает `kOn=1`, запрос не уходит.
   Если в последние 10 с этому карту ушёл `Stop`, маршал ждёт от платы
   `Stop OK` до 3 с и шлёт `/On6`, не глядя на телеметрию: она ещё помнит
   включённое реле, а поздний `Stop` уронил бы реле после `/On6` (02.11 у №3
   `Stop OK` пришёл через 2,7 с) [измерено].
3. Пауза `drive_settle` (0,6 с): плата дописывает свои настройки.
4. Если за это время заезд закрыла защита — `старт отменён: заезд уже закрыт`,
   `Start` не уходит.
5. **`{"Command":"Start","Length":<кусок>,"Speed":<лимит>}`** по вебсокету. Плата
   берёт лимит прямо из команды [разбор прошивки; проверено на №15 25.11].
   `Start` реле не включает, поэтому `/On6` идёт первым [разбор прошивки;
   измерено: `Start` без `/On6` → `kOn=0`]. Выход 7 (свет) `Start` поднимает сам.
6. Через 0,3 с — тот же лимит по HTTP `/maxSpeed` (если `speed_http = yes`).
7. Отсчёт заезда переносится на момент, когда ушёл `Start`: таймер в панели не
   убегает вперёд на время HTTP.
8. Строка в логе: `заезд 10 мин, скорость «Новичок» (50), кусками по 540 с
   (предел платы)` (для тест-драйва — `ТЕСТ-ДРАЙВ …`). У старта из CRM следом
   строка `СRM: старт заезда 10 мин` (буква С в `СRM` — кириллическая).

Отказы старта: карт не на связи; длительность не из списка (`presets` или
`test_presets`); на карте висит плашка о сбое платы (раздел 5). Панель сервер
не проверяет на «карт уже в заезде» (кнопки старта просто не видны у едущего
карта), API для CRM — проверяет.

### 3.2. Почему заезд идёт кусками по 540 с

После `Start` плата **ждёт фронта I/O** (переключатель I/O на корпусе
«выкл → вкл»). Пришёл — начинается её собственное «катание» на `Length` секунд
(`timeDriveOn=1`). Не пришёл за 600 с от последнего `Start` — плата сама
снимает реле и свет («закончилось время ожидания катания»)
[разбор прошивки, `ai/03-proshivka.md`].

Маршал включает реле сам (`/On6`), а I/O у гостя обычно уже включён — фронта нет,
и плата **весь заезд «ждёт»** (`timeDriveOn=0`). Её 600-секундный таймаут
ожидания и есть «предел платы 600 с», который 06.09 приняли за предел длины
заезда. Каждый `Start` в ожидании этот таймер перезапускает
[измерено 25.11 на №15: `Start` на 300-й секунде — реле снято на 906-й, а не на
600-й].

Поэтому маршал просит у платы кусок не длиннее `chunk_seconds` (540 с) и
продлевает его за `chunk_lead` (8 с) до конца.

**Длина куска** (`chunk_len`): весь остаток, если он не больше 540 с; иначе
540 с. Если после 540 с остался бы хвост меньше 30 с, кусок делится пополам
(при целых минутах и докатке 60 с так не бывает). Первый кусок планируется на
весь заезд **вместе с докаткой**.

| Заезд | Всего с докаткой 60 с | Продлений | Когда (от старта, ±2 с) |
|---|---|---|---|
| 1, 3, 5, 8 мин | ≤ 540 с | 0 | — |
| 9 мин | 600 с | 1 | ~532 с |
| 10 мин | 660 с | 1 | ~532 с (≈ 8:52) |
| 20 мин | 1260 с | 2 | ~532, ~1064 с |
| 30 мин | 1860 с | 3 | ~532, ~1064, ~1596 с |

Продление планируется, только если кусок кончается раньше конца заезда больше
чем на 30 с: ради последних секунд маршал карт не трогает.

### 3.3. Продление: три пути

| Путь | Когда | Что видит гость | Строка в логе |
|---|---|---|---|
| **Без Stop** (основной, с 25.11) | плата ждёт (`timeDriveOn=0`), реле включено (`kOn=1`), телеметрия не старше 14 с | ничего | `продление без Stop: кусок N с, лимит L` |
| **Через Stop** (старый) | плата считает сама (`timeDriveOn=1`), или телеметрия старая, или `kOn=0`, или без-Stop не подтвердилось за 20 с, или сокет мёртв | свет и реле гаснут ~2 с, контроллер перезагружается; **с нажатой педалью карт стоит, пока её не отпустят** | `продление заезда: кусок N с, всего осталось M с`; перед ним может быть `продление без Stop не подтвердилось за 20 с — продлеваю через Stop` |
| **Перевзвод** (с 25.11 20:12) | посреди куска пришло `timeDriveOn=1` при `kOn=1`, а продление ещё впереди | свет мигнёт ~2 с **один раз**, при отпущенной педали | `щелчок I/O посреди заезда, педаль отпущена (adcIn=N) — перевзвожу плату, дальше продления без Stop`, затем `перевзвод после щелчка I/O: кусок …` |

**Без Stop** (`renew_soft`). Одна команда
`{"Command":"Start","Length":N,"Speed":P}`. Если новая длина совпала бы с прошлой
`lengthDrive`, маршал отнимает секунду — только так по телеметрии видно, что
плата приняла именно этот `Start`. Через 1 с маршал сам просит `Status` и до 20 с
ждёт ответа с новым `lengthDrive` и `kOn=1`. Подтвердилось — лимит сверяется по
`Speed`; не совпал — досылается по HTTP. На докатке следом уходит `/Off7`:
`Start` зажигает свет, а на докатке он должен быть погашен.

20 с ожидания посчитаны с запасом: до 600 с у платы от начала куска в этот момент
ещё ~68 с, старому пути оставлено 30 с. Если в `marshal.conf` сделать кусок
длиннее, ждать можно меньше; меньше 5 с — сразу через Stop.

**Через Stop** (`renew_hard`):

1. `Stop` → ждать `Stop OK` от платы до 3 с.
2. Заезд за это время закрыли — `продление отменено: заезд уже закрыт`, реле не
   возвращается.
3. `/On6` всегда, не глядя на телеметрию (она снята до `Stop` и показывает
   `kOn=1`).
4. Пауза 0,6 с → `{"Command":"Start","Length":N}` (без `Speed`) → лимит по HTTP;
   на докатке ещё `/Off7`.
5. Проверка реле (`renew_check`): ~21 с смотрит свежие `Status`. `kOn=0` —
   `после продления реле выключено (kOn=0) — повторяю разрешение`, не больше
   двух раз; потом `после продления реле так и не включилось — карт стоит,
   проверьте`.

До 02.11 реле падало после продления в 2 случаях из 252 (плата отрабатывала
`Stop` позже `/On6`) [измерено]. С тех пор маршал ждёт `Stop OK`.

**Перевзвод** (`rearm_tick` → `ride_rearm`, #22). Если гость включил I/O после
старта, плата начинает считать заезд сама, и `Start` её уже не продлевает
[разбор прошивки; сами не замеряли]. Тогда плановое продление пошло бы через
`Stop` — с риском, что гость в этот момент держит педаль, а контроллер с
нажатой педалью не поедет (№13 25.11 19:03 [измерено, владелец]). Поэтому
маршал делает тот же `Stop`/`Start` **сразу после щелчка и только с отпущенной
педалью**:

- условия: свежая телеметрия (снята после нашего `Start`) с `timeDriveOn=1` и
  `kOn=1`; в заезде будет ещё продление; до конца куска больше 13 с; другое
  продление не идёт; с прошлого перевзвода прошло больше 8 с;
- педаль нажата (`adcIn` > `rearm_pedal_max`, по умолчанию 55) — один раз пишет
  `щелчок I/O посреди заезда, педаль нажата (adcIn=N) — перевзведу, как только
  отпустят` и ждёт;
- перед `Stop` маршал просит свежий `Status` (до 3 с) и ещё раз проверяет педаль;
- не больше **2 перевзводов** за заезд. Дальше один раз
  `щелчок I/O снова после 2 перевзводов — больше не перевзвожу, продления через
  Stop` — защита от платы, у которой фронт I/O бывает сам;
- после `Stop`+`Start` плата снова «ждёт»: I/O уже включён, нового фронта нет,
  и все следующие продления бесшовные [измерено: №13 25.11 в 19:12:37 и
  19:21:30 после `Stop` в 19:03:41];
- в заезде из одного куска (до 8 мин) перевзвода нет: продлевать нечего;
- выключить: `rearm_pedal_max = 0` в `marshal.conf` и перезапуск маршала.

Порог 55: педаль отпущена 40–49, до упора 180–189, без питания реле ~2, `255` —
сбой шины [измерено 25.11 по шести картам: №2, 11, 12, 13, 14, 15].

Перевзвод на живом карте до 20:16 25.11 ещё не видели [измерено].

**Правило для площадки:** I/O включать **до старта** — тогда весь заезд
бесшовный. Включили после старта — свет мигнёт один раз (перевзвод), дальше
бесшовно.

### 3.4. Докатка

Когда оплаченное время вышло (`t_paid`), заезд переходит в фазу `crawl` на
`crawl_seconds` (на кассе 60 с):

- карт **не останавливается**: кусок и так покрывает докатку;
- гаснет выход 7 (`/Off7`) — по погасшей подсветке гость понимает, что время
  вышло;
- лимит падает до докаточного: свой у карта (`<DUUID>.crawl` в `karts.conf`) или
  общий `speed_crawl` (на кассе 20);
- строка `докатка: выход 7 снят, лимит L`.

Докатка считается от конца оплаты: карт, вернувшийся на связь (или маршал,
поднятый после перезапуска) уже после конца оплаты, получает остаток докатки,
а не целую.

**Сторож докатки.** Если по свежей телеметрии `driveOn` не 1, с прошлой отправки
прошло больше 8 с и до конца больше 6 с, маршал повторяет набор (свет и лимит):
`докатка: карт стоит, повторяю набор команд`, не больше двух раз.

`crawl_seconds = 0` — докатки нет: по концу оплаты заезд сразу закрывается.

### 3.5. Конец заезда

`t_end` прошёл → `ride_finish`:

1. Заезд закрывается **на сервере сразу** (под замком, чтобы сторож и защита не
   закрыли его дважды), CRM получает одно событие `finish`.
2. Слепок выбрасывается, `rides-state.json` переписывается: закрытый заезд не
   оживёт после перезапуска.
3. `Stop` по вебсокету, `/Off6` (реле), `/On7` (свет свободного карта). Реле и
   свет идут через желаемое состояние: не дошло — дошлётся.
4. Строка с причиной: `заезд закончен`, `остановлен вручную` или
   `ЗАЩИТА: …`.

Останавливает только снятие реле: лимит 0 карт не останавливает, при `kOn=1`
карт едет самым малым газом [измерено 10.09; разбор прошивки: первые 85 единиц
газа проходят при любом лимите].

### 3.6. Остановка вручную

| Кнопка | Что делает |
|---|---|
| «Стоп» на карточке в панели | закрывает заезд этого карта, как в 3.5 (`остановлен вручную`) |
| «Стоп» на карточке «нет связи» | снимает заезд с сервера (`заезд снят вручную, карт не на связи`). Плата узнает при возвращении: она вернётся свободной, и маршал снимет с неё реле |
| «⛔ СТОП ВСЕМ» в панели и админке | `Stop` и `/Off6` всем картам на связи и снятие заездов у картов без связи. **Без подтверждения**: одно нажатие останавливает весь парк, включая гостей на трассе |
| `/api/v1/stop`, `/api/v1/stopall` из CRM | то же, но только для картов **на связи** (раздел 9) |

У **свободного** карта в панели кнопки «Стоп» нет (раздел 6). Если свободный
карт держит реле (красная плашка «едет сам»), остановить его можно из админки
(раздел 7.2) или выключив карт.

### 3.7. Обрыв посреди заезда и перезапуск маршала

**Обрыв.** Заезд остаётся в слепке, таймер в панели идёт дальше: карт едет по
своему таймеру. Вернулся — маршал **сначала спрашивает**, едет ли он
(`Status`, до 5 с):

- `driveOn=1` — карт только терял вебсокет, его таймер цел: `вернулся на связь и
  едет сам — не трогаю. У сервера N с, карт: …`;
- `driveOn=0` — плата перезагрузилась и потеряла реле, лимит и таймер. Маршал
  возвращает заезд: `/On6`, пауза, `Start` на остаток (вместе с докаткой), лимит
  по HTTP, на докатке `/Off7`: `карт вернулся стоящим — возвращаю ride|crawl,
  осталось N с, лимит L`.

Если заезд закончился, пока карта не было, его снятие (`/Off6`) дошлёт желаемое
состояние при возвращении.

**Перезапуск маршала.** Идущие заезды и хвост журнала событий (30 мин) лежат в
`rides-state.json` (раздел 12). При запуске маршал кладёт живые заезды в слепки:
`Заезды до перезапуска: возвращено N — 13 (ride, ещё 312 с), …` или
`Заезды до перезапуска: идущих не было.` Карты переподключаются за 2–3 с и
забирают заезды обычным возвращением. Время абсолютное: простой не дарится и не
возвращается, заезд с прошедшим концом не поднимается. Правило клуба:
перезапуск любой части системы оплаченное время не теряет (10.10 закрыли CRM
посреди восьми заездов — с тех пор так).

После перезапуска у свободных картов в логе бывает `ЗАЩИТА: плата в местном
режиме, катание не начато` — это норма: пока маршала не было, платы взвели
местный режим и снимают его сами, увидев сервер [измерено 25.11].

Сессии входа хранятся в памяти: после перезапуска панель и админка просят войти
заново (если на панели задан `marshal_pass`).

### 3.8. Пример: заезд 10 минут из CRM, I/O включён до старта

| Время от старта | Что делает маршал | Что видно |
|---|---|---|
| 0 с | `/On6` (если `kOn=0`), 0,6 с, `Start{Length 540, Speed L}`, 0,3 с, `/maxSpeed L` | `kOn=1`, `kOn1=1`, `timeDriveOn=0`, `lengthDrive=540` |
| каждые 6 с | `Status`, строка `СВЕРКА ride: сервер N с \| карт …` | |
| ~532 с | продление без Stop: `Start{Length 128, Speed L}` | `lengthDrive=128`, реле не падает |
| 600 с | докатка: `/Off7`, `/maxSpeed 20` | `kOn1=0`, таймер в панели — «время доехать до бокса» |
| 660 с | `Stop`, `/Off6`, `/On7` | `kOn=0`, `kOn1=1`, `заезд закончен` |

## 4. Скорость: откуда берётся лимит

### 4.1. Что значит число

Лимит — `maxSpeed` платы, шкала **0..100** (до 12.09 маршал по ошибке умножал на
2,55). Это потолок газа, а не процент скорости: первые 85 единиц газа
(≈ 1,67 В) проходят на контроллер при любом лимите, поэтому лимит 0% тоже едет, а
60% дают больше 60% скорости [разбор прошивки, подтверждено замерами;
`ai/03-proshivka.md`, раздел 4]. Педаль в пол: лимит 20% → `adc0` ≈ 104, 50% →
≈ 134, 100% → ≈ 184 [измерено 21–24.11]. Скорость ещё задаёт переключатель
高中低 на корпусе, мимо платы.

### 4.2. Источники лимита

| Откуда старт | Каким лимитом едет заезд |
|---|---|
| **панель маршала** | градация скорости (номер градации присылает браузер) → своё значение карта в таблице «Скорость по картам» (`<DUUID>.preset.<градация>` в `karts.conf`) → нет своего — общее значение градации (`speeds` в `marshal.conf`) |
| **CRM** (`/api/v1/start`) | «ползунок» карта: `<DUUID>.speed` в `karts.conf`. Если CRM прислала `speed`, он **сначала сохраняется** как ползунок карта, потом им стартует заезд. Нет ползунка — `speed_default` (50) |

- Лимит фиксируется в заезде: продления и возвращение после обрыва ставят его же.
- В логе старта из CRM написано `скорость «<первая градация>» (L)`, но L — это
  ползунок, а не градация: подпись ничего не значит.
- На кассе с 25.11 18:52: общие градации `Обычный 70, Новичок 50, Профи 100`, у
  всех 17 записей `karts.conf` свои значения Новичок 50, Обычный 70, Профи 90
  (решение владельца).

**В панели нет выбора градации.** В `panel.html` нет кнопок градаций (их нет с
первой версии в git). Номер градации панель берёт из памяти браузера
(`localStorage`, ключ `mk_speed`), а если там пусто — **среднюю по порядку**
градацию из строки `speeds`. При порядке на кассе `Обычный, Новичок, Профи`
средняя — «Новичок». Значит, старты из панели, скорее всего, все идут на
«Новичке» (50%). Проверить: строки `заезд N мин, скорость «…»` без следующей
строки `СRM: старт` (`ai/10-zhurnaly.md`) **[не проверено]**.

### 4.3. Смена лимита посреди заезда

| Откуда | Что меняется |
|---|---|
| ползунок на карточке в панели + «ОК» | сохраняется ползунок карта (`.speed`, его потом возьмёт и CRM) и лимит идущего заезда. Карту уходит сразу, только если фаза `ride`; на докатке — только запоминается |
| `/api/v1/speed` из CRM | то же, но уходит сразу и в фазе `ride`, и на **докатке**: докаточный лимит перебивается лимитом заезда до конца (так в коде; задумано ли — **[не проверено]**) |

Ползунок у **свободного** карта показывает и меняет лимит для стартов из CRM; на
старты из панели он не влияет.

### 4.4. Куда уходит лимит

| Момент | Как |
|---|---|
| старт | в `Start` (`Speed`) и следом HTTP `/maxSpeed` |
| продление без Stop | в `Start` (`Speed`); не совпал в телеметрии — HTTP |
| продление через Stop, возвращение после перезагрузки | `Start` без `Speed`, затем HTTP `/maxSpeed` |
| докатка | HTTP `/maxSpeed` |

HTTP-лимит уходит, только если `speed_http = yes`. На кассе он включён: в
журналах сотни строк `лимит N% → …/maxSpeed?maxSpeed=N — ок` (663 за 21–24.11,
без ошибок) [измерено]. При `speed_http = no` докатка и продления через Stop
остались бы без лимита: после `Stop` плата берёт `maxSpeed` из своего
`config.json` (70) [разбор прошивки].

## 5. Защита по телеметрии и сторожа

### 5.1. Защита (PR #20)

Каждый ответ `Status` проверяется (`guard_check`). Две беды, которые плата сама
не лечит [разбор прошивки]:

| Признак | Что это | Что делает маршал |
|---|---|---|
| `adcIn`, `adc0` или `adc3` = **255**, реле включено | сбой шины I2C платы: несчитанное значение приходит как 255, педаль читается «в пол», газ уходит **выше лимита** (170 при 50%, 255 при 100%) | заезд закрывается (`ЗАЩИТА: сбой платы: adcIn=255 — педаль не читается, газ может уйти выше лимита. К гостям не выпускать, проверить плату — останавливаю карт`); у свободного карта — `Stop` и `/Off6` |
| то же, реле выключено | то же | только плашка и запись в лог |
| `localModeWaitStart=1` и катание идёт (`kOn=1` или `timeDriveOn=1`), у маршала карт свободен | местное катание без оплаты: пока сервера не было, гость щёлкнул I/O | `Stop` и `/Off6` (`ЗАЩИТА: катается в местном режиме без оплаты — сервера не было на связи — останавливаю карт`) |
| `localModeWaitStart=1`, катание не начато | местный режим взведён; увидев сервер, плата снимает его сама | только запись: `ЗАЩИТА: плата в местном режиме, катание не начато` |
| `localModeWaitStart=1` посреди оплаченного заезда | плата досчитывает своё | только запись: `ЗАЩИТА: плата в местном режиме посреди заезда` |

- Живая педаль до 255 не доходит (в пол 182–216), `adc0`/`adc3` выше 220 не бывают:
  ложных срабатываний на исправном карте быть не должно [измерено]. 254 — не сбой.
- Останов — не чаще раза в 5 с на карт; запись без останова — не чаще раза в
  минуту.
- **Плашка** «Защита: …» висит в панели 10 минут после последнего сбойного
  `Status`.
- **Блок старта.** Пока висит плашка о `255`, старт на этот карт отклоняется и
  в панели, и в CRM: `карт неисправен — сбой платы: …`. Снять раньше — только
  перезапуском маршала. Плашка о местном режиме старт не блокирует.
- Если, пока шла остановка, маршал начал на карте оплаченный заезд, защита
  местного режима его не трогает (`ЗАЩИТА: на карте начат заезд — местный режим
  не трогаю`). Сбой `255` закрывает и такой заезд.

№12: `adcIn=adc0=255` минутами во время заездов 09.09 и эпизоды 28.10, 31.10,
22.11 [измерено]. Карт с этим сбоем к гостям не выпускать (`ai/09-karty.md`).

### 5.2. Сторож свободного карта

Свободный по мнению маршала карт с `kOn=1` дольше 10 с (кроме первых 15 с после
конца его заезда и первых 20 с после подключения):

- в панели карточка «едет сам», красная плашка;
- в логе раз в 30 с `ВНИМАНИЕ: driveOn=1 вне заезда уже N с — проверь карт,
  автоматический Stop отключён` (в тексте `driveOn`, а проверяется `kOn`);
- в `/api/v1/karts` у карта `alarm: true`.

**`Stop` сторож не шлёт — сознательно.** Он судит по незнанию сервера: после
перезапуска маршала все карты возвращаются «едущими», и автоматический `Stop`
ушёл бы на весь парк разом, под гостями. Решение остановить машину с человеком
принимает маршал. Защита из 5.1 останавливает сама, потому что о беде говорит
сама плата.

## 6. Панель маршала (`/`)

**Адрес:** `http://localhost:8080/` на кассе, `http://192.168.1.50:8080/` с
планшета или телефона в Wi-Fi картов. Если в `marshal.conf` задан
`marshal_pass`, сначала страница входа (пароль — FireDrift_Access); сессия
живёт 12 часов и пропадает при перезапуске маршала. Открытый двойным щелчком
файл `panel.html` не работает — панель сама об этом скажет.

**Шапка:** дата и часы сервера, ссылка «админка». Красная полоса «Нет связи с
сервером. Карты сейчас не управляются.» — браузер не достучался до маршала.

**Карточки** по одной на карт, порядок постоянный (по имени: «Карт 2» раньше
«Карт 10»). Цвет полосы слева и слово сверху:

| Состояние | Слово | Цвет | Что на карточке |
|---|---|---|---|
| свободен | `свободен` | зелёный | ползунок скорости, кнопки «поехали на» N минут, ряд «тест-драйв» |
| заезд | `заезд` | синий | ползунок, большой таймер, «запуск» и «конец», кнопка «Стоп» |
| тест-драйв | `тест-драйв` | фиолетовый | то же, что заезд |
| докатка | `докатка` | оранжевый | таймер остатка докатки («время доехать до бокса»), «запуск» и «стоп», «Стоп» |
| нет связи, заезд идёт | `нет связи` | серый, бледный | «Связи с картом нет, но заезд идёт…», таймер, «Стоп» |
| нет связи, свободен | `нет связи` | серый | «Карт не отвечает. Проверь питание и Wi-Fi.» (10 минут, потом карточка исчезает) |
| едет сам | `едет сам` | красный | плашка «Карт едет вне заезда. Сервер шлёт «Стоп». Подойди к карту.» — **текст неверен: сервер `Stop` не шлёт** (раздел 5.2) |
| защита | как было | красный | плашка «Защита: <текст сервера>», 10 минут |

- **Таймер** — сколько осталось оплаченного времени (`t_paid` − сейчас), на
  докатке — сколько осталось докатки. Под ним «осталось из N мин · <градация>»
  или «тест-драйв, N мин». Ниже — часы **запуска** и **конца** оплаты (на
  докатке — «стоп»), с датой. Как перевести таймер в часы — `ai/10-zhurnaly.md`.
- **Ползунок скорости** 0..100 с шагом 5, отметки «новичок» 30, «средний» 50,
  «быстро» 75. Уходит на сервер **только по кнопке «ОК»** (раздел 4.3).
- **Кнопки времени** — из `presets`, **тест-драйва** — из `test_presets`
  (пусто — ряда нет).
- **Выбора градации нет** (раздел 4.2).
- **«⛔ СТОП ВСЕМ»** внизу — без подтверждения (раздел 3.6).
- Состояние обновляется раз в секунду, таймеры — 4 раза в секунду с поправкой на
  часы сервера, настройки — раз в 30 с (правки из админки подхватываются сами).

## 7. Админка (`/admin`)

**Адрес:** `http://localhost:8080/admin` (или `192.168.1.50:8080/admin`). Вход —
`admin_user` и `admin_pass` (FireDrift_Access). Пароль вводит человек сам. Неверный
пароль — пауза 1 с. «выйти» — конец сессии. Предупреждение сверху: перед
первым пуском колёса вывешены, главный выключатель под рукой, `maxSpeed 40`;
запросы к плате строго по одному, не спамить кнопками.

### 7.1. Блок «Парк»

Таблица: «Карт» (номер), DUUID, состояние (`свободен`, `заезд`, `тест-драйв`,
`докатка`, `нет связи`, `едет сам`), «Осталось», адрес соединения, «Молчит»
(секунд с последнего кадра), выжимка телеметрии (`driveOn kOn adcIn aIn Speed`).
Пусто — «Ни один карт не подключился…».

Ниже ручные команды **по вебсокету** (через `/api/admin/send`):

| Кнопка | Что уходит |
|---|---|
| `Status` | `{"Command":"Status"}` |
| `Start` с полем «Length, с» (60) | `{"Command":"Start","Length":N}` |
| `Stop` | `{"Command":"Stop"}` |
| `MaxSpeed` + «Применить» | `{"Command":"MaxSpeed","MaxSpeed":N}`. По разбору прошивки плата читает в этой команде поле `Speed`, а не `MaxSpeed` [разбор прошивки] — что делает эта кнопка на живой плате, **[не проверено]**. Лимит надёжнее ставить по HTTP (7.8) |
| «Отправить как есть» | любой JSON из поля; регистр важен: `Stop`, а не `stop` (иначе плата отвечает `error`) |
| «⛔ СТОП ВСЕМ» | как в панели |

**Внимание: список «команды для» по умолчанию стоит на «всех картов».** Кнопка
`Start` или `Stop` без выбора карта уйдёт **всем картам на связи**. Перед любой
командой выбрать карт. Ручной `Start` не создаёт заезда на сервере: маршал о нём
не знает, не продлевает, не делает докатку и не закрывает (`ai/06-instrumenty.md`,
раздел 6).

### 7.2. Как остановить свободный карт с поднятым реле

В панели у свободного карта кнопки «Стоп» нет. В админке: «команды для» →
нужный карт → `Stop`; затем в «Прямом HTTP к плате» выбрать этот карт и нажать
`Off6`. В «Живых полях» должно стать `kOn=0`.

### 7.3. Блок «Настройки заезда»

Сохраняется кнопкой «Сохранить» в `marshal.conf` и применяется сразу, без
перезапуска («Отменить правки» — вернуть поля к сохранённому):

| Поле | Ключ | Ограничения |
|---|---|---|
| Кнопки времени, мин | `presets` | 1..180, до 6, хотя бы одна. **Это же список длительностей, разрешённых CRM** |
| Кнопки тест-драйва, мин | `test_presets` | 1..180, до 4; пусто — ряд скрыт |
| Градации скорости | `speeds` | подпись до 16 символов без `#` и `=`, значение 0..100, до 4, хотя бы одна. **Порядок важен** (раздел 4.2) |
| Скорость докатки, % | `speed_crawl` | 0..100 |
| окно, секунд | `crawl_seconds` | 0..3600; 0 — без докатки |
| Имена картов | `karts.conf` | DUUID (только цифры) → номер на кузове (до 12 символов) |

Переименование градации отрывает от неё значения в таблице «Скорость по
картам»: строки `<DUUID>.preset.<старое имя>` остаются в `karts.conf`, но больше
не используются.

Кнопка «+ карт» добавляет строку; карты, которые уже подключались без имени,
подставляются сами.

### 7.4. «Докатка по картам»

Строка на каждый подключённый карт: свой лимит докатки 0..100 и «ОК». Пусто —
общий `speed_crawl`. Сохраняется сразу в `karts.conf` (`<DUUID>.crawl`), пишется
в лог `лимит докатки: …`. Нужен, когда общий лимит на этом карте ползёт или,
наоборот, едет слишком быстро: контроллеры откалиброваны по-разному.

### 7.5. «Скорость по картам»

Таблица «карт × градация»: какой лимит получает карт в каждой градации при старте
**из панели**. Пусто — общее значение градации (оно же подсказка в поле).
«ОК» сохраняет строку карта сразу в `karts.conf` (`<DUUID>.preset.<градация>`),
в лог `лимиты по градациям: …`. На старты из CRM не влияет.

### 7.6. «Живые поля»

Выбранный карт, все поля его последней телеметрии плиткой. Поле, которое
изменилось, на секунду подсвечивается синим: «нажми педаль и смотри, какое поле
дёрнулось». Страница обновляется раз в секунду, но телеметрия у маршала
меняется раз в `status_period` (6 с; надпись в админке «раз в 3 с» устарела).

### 7.7. «Журнал вебсокета»

Последние 200 строк обмена маршала с картами (в памяти хранится 400, после
перезапуска пусто): `→` команда, `←` ответ, `·` событие сервера. Те же строки
есть в файловом логе.

### 7.8. «Прямой HTTP к плате»

Только с кассы или из сети картов. Выбрать карт в списке (подставится его IP из
телеметрии) или вписать IP.

- **«🔍 Найти карты в сети»** — SSDP-поиск и опрос порта 80 во всех подсетях /24
  кассы плюс «доп. подсети» (по умолчанию `10.20.0, 192.168.1`). Касса сидит и в
  сети DC, поэтому поиск опрашивает и её устройства (автоматы, терминал оплаты).
  Пользоваться по делу.
- **Чтение** (ничего не меняют): `config.live.json` (вся телеметрия),
  `config.setup.json`, `setup.json`, `config.json`, `index.json`, `Sensors`,
  `rcVal`, `charts.json`, `raceslist.txt` (журнал заездов платы),
  `reboots.json`, `localdrives.json` (местные заезды), `list?dir=/` (файлы),
  `description.xml`.
- **«Обслуживание платы»** — кнопки, меняющие состояние карта: `On6`, `Off6`
  (реле), `On7`, `Off7` (свет) — это **не** запуск заезда; `maxSpeed` 0..100
  «Записать в плату»; часовой пояс (`timeZone`, «Кызылорда = 5»);
  «Перезагрузить плату» (с подтверждением; карт пропадёт секунд на 20).
- Смены Wi-Fi (`/ssid`, `/ssidap`, `/wifioff`) нет намеренно: ошибка уносит
  карт из сети, вернуть можно только по USB или через его точку `ktWiFi`.
- Сеттеры платы **без параметров стирают настройки** (так однажды стёрли имя
  устройства), поэтому у каждого действия своя кнопка, а не поле адреса.
- «Лог обмена» — что ушло и что ответила плата, с временем ответа в мс. Живёт
  только в браузере.

### 7.9. Ручная отправка: `/api/admin/send` и `/api/admin/http`

Оба адреса — только с сессией администратора (кука `mk`), только `POST` с JSON.

| Адрес | Тело | Ответ |
|---|---|---|
| `/api/admin/send` | `{"kart": "<DUUID или *>", "cmd": "<JSON-строка команды>"}` | `{"ok": true, "sent": ["<DUUID>", …]}` или `{"ok": false, "error": "не JSON: …"}` |
| `/api/admin/http` | `{"ip": "<адрес платы>", "path": "<путь>"}` | `{"ok", "url", "status", "ms", "body"}` или `{"ok": false, "error", "ms"}` |

- `cmd` должен быть правильным JSON, иначе отказ. `kart = "*"` или пусто — всем
  картам на связи.
- `/api/admin/http` принимает **любой путь**, в том числе опасные сеттеры:
  кнопки админки — единственная защита. Запрос встаёт в общую очередь HTTP к
  платам и держит её до 8 с.
- Когда и что безопасно слать — `ai/06-instrumenty.md`, раздел 6.

## 9. API для CRM

Подробно — `docs/api.md` в репозитории. Коротко:

- `http://<касса>:8080/api/v1/…`, токен в заголовке `Authorization: Bearer
  <api_token>` или `X-Api-Token`. Пустой `api_token` — API выключен (503).
  Ответы: 200, 400 плохие параметры, 401 токен, 404 карт не найден.
- Методы: `GET karts`, `POST start` (`kart`, `minutes`, `test`, необязательный
  `speed`), `POST stop`, `POST speed`, `POST stopall`, `GET events?since=`.
- Карт — DUUID или номер на кузове.
- На кассе CRM ходит через мост `clubbridge` на `127.0.0.1:8080` с токеном
  `karts_token`. **Сменили `api_token` в `marshal.conf` — поменять и
  `karts_token` в `bridge\clubbridge.json`**, иначе CRM не сможет запускать
  заезды (401).

Особенности по коду, которых нет в `docs/api.md`:

- `minutes` должен быть из `presets` (для теста — из `test_presets`). Убрали
  длительность из кнопок админки — CRM получит 400 на эту длительность.
- `speed` в `start` и `speed` в `speed` **сохраняются навсегда** как ползунок
  карта (`.speed`).
- `stop` и `stopall` работают только для картов **на связи**: карт без связи —
  404, его заезд остаётся на сервере и продолжится, когда карт вернётся. Панель
  такой заезд снять умеет.
- `alarm` в `karts` — только сторож свободного карта (5.2); плашка защиты (5.1)
  в API не видна.
- Журнал событий: последние 500 в памяти; события за последние 30 мин
  переживают перезапуск маршала (лежат в `rides-state.json`). У `start` есть ещё
  поля `speed` (лимит) и `crawl_seconds`.

## 10. `marshal.conf` — все ключи

Файл рядом с `marshal.py`. Создаётся сам при первом запуске (со случайным
`admin_pass`). Формат `ключ = значение`, `#` — комментарий. **Значения паролей и
токена — только в FireDrift_Access, сюда не писать.**

«Код» — значение, если строки нет совсем; «шаблон» — что пишет новый файл;
«касса» — значение на кассе 25.11 по записям агента на кассе.

| Ключ | Код | Шаблон | Касса | Что задаёт |
|---|---|---|---|---|
| `admin_user` | `admin` | `admin` | — | логин админки |
| `admin_pass` | — | случайный | секрет | пароль админки. Только в файле |
| `marshal_pass` | пусто | пусто | секрет (задан) | пароль панели; пусто — панель без входа |
| `port` | 8080 | 8080 | 8080 | порт. Карты звонят на 8080 — не менять |
| `host` | `0.0.0.0` | `0.0.0.0` | — | на каких адресах слушать |
| `presets` | 5,10,20,30 | 5,10,20,30 | 1,10,20,30 | кнопки времени и длительности для CRM, 1..180 мин |
| `test_presets` | 1,2,3 | 1,2,3 | 1,3,5 | тест-драйв; пустая строка — выключен |
| `speeds` | `Новичок:30, Обычный:60, Быстро:85` | то же | `Обычный:70, Новичок:50, Профи:100` | градации `подпись:значение`, 0..100, до 4 |
| `speed_crawl` | 15 | 15 | 20 | общий лимит докатки, 0..100 |
| `crawl_seconds` | **0** | 60 | 60 | длина докатки, 0..3600 с; 0 — без докатки |
| `crawl_mode` | `restart` | `restart` | — | **кодом не используется**, только печатается при запуске (раздел 14) |
| `drive_on` | `On6` | `On6` | — | HTTP-путь включения реле; пусто — реле не трогать |
| `drive_off` | пусто (тогда `Off6` из `drive_on`) | `Off6` | — | путь выключения реле |
| `drive_timeout` | 3 | 3 | — | таймаут HTTP к плате, 1..20 с |
| `drive_settle` | 0,6 | 0,6 | — | пауза после `/On6` перед `Start`, 0..5 с |
| `speed_http` | **no** | yes | yes (по журналам) | дублировать лимит по HTTP `/maxSpeed` (раздел 4.4) |
| `status_period` | 6 | 6 | 6 | период опроса каждого карта, 2..60 с |
| `rearm_pedal_max` | 55 | 55 | нет строки → 55 | порог «педаль отпущена» для перевзвода, 0..254; 0 — перевзвод выключен |
| `syslog_port` | 0 | 0 | **[не проверено]** | UDP-порт приёма журнала роутера; 0 — не слушать |
| `syslog_from` | `192.168.1.1` | `192.168.1.1` | — | с каких адресов принимать, через запятую; пусто — с любых |
| `kart_user`, `kart_pass` | — | заводские | секрет | логин и пароль веб-морды платы (одинаковые на всех платах) |
| `speed_default` | 50 | нет | 50 | лимит карта без своего ползунка |
| `api_token` | пусто | нет | секрет | токен API для CRM; пусто — API выключен |
| `chunk_seconds` | 540 | нет | 540 | длина куска заезда, 0..3600 с. **0 — без кусков: плата снимет реле через 600 с** |
| `chunk_lead` | 8 | нет | 8 | за сколько секунд до конца куска продлевать, 2..60 |
| `speed_fast` | `On7` | нет | — | путь «свет включить» (обычный заезд); пусто — выход 7 не трогать |
| `speed_slow` | `Off7` | нет | — | путь «свет выключить» (докатка) |
| `http_parallel` | 1 | нет | — | сколько HTTP к разным платам одновременно, 1..6. Больше 1 — больше передатчиков в эфире сразу; поднимать по одному и смотреть лог |
| `http.<DUUID>` | — | нет | — | `адрес:порт` для HTTP к этой плате вместо IP из телеметрии (карт за NAT) |
| `kart.<DUUID>` | — | старый формат | — | номер на кузове; при первом сохранении из админки переезжает в `karts.conf` |

**Правила правки:**

- Из админки меняются и сразу применяются: `presets`, `test_presets`, `speeds`,
  `speed_crawl`, `crawl_seconds`, имена картов. Маршал переписывает только эти
  строки, остальные строки и комментарии сохраняются.
- Всё остальное читается **только при запуске**: правка руками действует после
  перезапуска маршала (между группами).
- Пароли и токен меняются только в файле, руками. После смены `api_token` —
  обновить мост (раздел 9).
- Ловушка: если строки нет, у `speed_http` и `crawl_seconds` значение из кода
  другое, чем в шаблоне (`no` и 0). Удалить эти строки — значит выключить
  HTTP-лимит и докатку.

## 11. `karts.conf`

Файл рядом с `marshal.py`, **при обновлении маршала не заменяется** и в git не
кладётся. На кассе — `C:\FireDrift-тест\marshal\karts.conf`. Формат:

```
<DUUID>                    = <номер на кузове>
<DUUID>.speed              = <ползунок, 0..100>      старты из CRM
<DUUID>.crawl              = <лимит докатки, 0..100>  нет строки — общий speed_crawl
<DUUID>.preset.<градация>  = <лимит, 0..100>          старты из панели; нет — общее значение
```

- Пишется маршалом целиком, по DUUID по порядку, через временный файл.
- Читается **только при запуске**. Правка руками при работающем маршале
  пропадёт при первом же сохранении из панели или админки: маршал перепишет
  файл из памяти. Править руками — только остановив маршал (между группами) или
  через админку.
- Имя градации — часть ключа: переименовали градацию — старые строки
  `.preset.` больше не работают.
- Таблица «номер ↔ DUUID» и её неточности (№10, №14, запасные платы) —
  `ai/09-karty.md`. Копия файла нужна и на ноутбуке для `Какой карт.bat`.

## 12. `rides-state.json`

Файл рядом с `marshal.py`, пишется сам, в git не кладётся:

```json
{"rides": {"<DUUID>": {"phase": "ride", "minutes": 10, "limit": 50, "t0": …,
                       "t_paid": …, "t_end": …, "test": false, "chunk_end": …, …}},
 "events": [ …события за последние 30 мин… ],
 "saved": <время записи>}
```

- Внутри — идущие заезды (свои и картов без связи) и хвост журнала событий для
  CRM. Время — абсолютное (Unix).
- Пишется, только когда что-то поменялось (проверка раз в секунду), целиком,
  через `.tmp` и замену: оборванная запись оставляет прежний файл.
- При запуске: живые заезды → слепки, кончившиеся пропускаются, заезд с концом
  дальше, чем его длина с докаткой (часы прыгнули), — тоже.
- Не записался — в логе `ВНИМАНИЕ: заезды не записаны в …: … — после
  перезапуска сервера они не вернутся`.
- **Руками не править. При откате версии из копии его не возвращать.**
