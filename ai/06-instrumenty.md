# Инструменты и пошаговые процедуры

Как подготовить ноутбук, узнать карт по плате, прошить плату, снять USB-лог,
прочитать живые поля, дать плате ручную команду, выкатить новый маршал и
проверить его. У каждой процедуры: зачем, что нужно, шаги, что должно
получиться, частые ошибки.

Метки: **[измерено]** (замер или журнал, с датой), **[владелец]**,
**[разбор прошивки]**, **[не проверено]**. Поведение программ из репозитория
(`marshal.py`, `usb_log.py`, `kakoy_kart.py`, `fakekart.py`) описано по их коду,
без меток.

Связанные файлы: безопасность — `ai/01-bezopasnost.md`; плата и пятаки —
`ai/02-zhelezo.md`; прошивка изнутри и карта флеша — `ai/03-proshivka.md`;
маршал — `ai/04-marshal.md`; сеть — `ai/05-set.md`; нормы полей —
`ai/07-izmereniya.md`; карты — `ai/09-karty.md`; журналы — `ai/10-zhurnaly.md`.

---

## 0. Общие правила для всех процедур

1. **Работа руками на карте** — только когда гостя нет, заезд закрыт (в панели
   карт «свободен»), карт на подставке (колёса в воздухе) и в телеметрии
   `kOn=0`. При `kOn=1` карт поедет от педали (`ai/01-bezopasnost.md`).
2. **Перед работой с платой — снять батарею** (кроме USB-лога с кабелем с
   изолентой, раздел 4). USB и батарея одновременно — плата получает 5 В с двух
   сторон: для короткого замера можно, для работы нет (`docs/montazh.md`).
3. **Один шаг — один ответ человека.** После шага спросить, что он видит.
4. **Перезапуск маршала и всё, что роняет связь у всех картов, — только между
   группами**, время выбирает владелец. Окно CRM не закрывать.
5. **Секреты** (пароли, токен, MAC, образы прошивки) — только в FireDrift_Access.
   Пароли человек вводит сам. Образы и дампы флеша содержат пароль Wi-Fi —
   не класть в git, не пересылать.
6. Команды для кассы — PowerShell 5.1, короткими блоками по одной команде:
   длинные однострочники при вставке ломаются.

## 1. Ноутбук для работы с платой

**Зачем.** Через USB ноутбук читает DUUID платы (какой это карт), шьёт плату и
пишет её USB-лог. Ещё на нём гоняют проверки маршала.

### 1.1. Что стоит на ноутбуке владельца [измерено 01–02.11, 25.11]

| Что | Версия, где |
|---|---|
| Python | 3.15.2, запускается командой **`py`** |
| esptool | 5.3.1 (с ним ставится `pyserial`, он нужен `usb_log.py` и `kakoy_kart.py`) |
| драйвер USB-переходника D1 mini | CH340 от WCH, версия 3.9.2024.9 |
| репозиторий | `C:\Users\wallg\OneDrive\Desktop\CrazyDrift\kart-marshal\` |
| запасной Python | 3.11 из KiCad: `"C:\Program Files\KiCad\10.0\bin\python.exe"`, запускать с `-I` |

### 1.2. Как поставить с нуля

1. Python с python.org. При установке — галочка «Add to PATH» и лаунчер `py`.
   Проверка: `py --version` → `Python 3.x.y`.
2. **Только для Python 3.15:** у PyYAML (его требует esptool) нет готовой сборки
   под 3.15, компилятора на ноутбуке нет. Сначала ставим PyYAML без
   C-расширения — две команды PowerShell подряд в одном окне:

   ```powershell
   $env:PYYAML_FORCE_LIBYAML='0'
   ```

   ```powershell
   py -m pip install pyyaml==6.0.3
   ```

   Тот же приём нужен при любой переустановке или обновлении esptool.
3. `py -m pip install esptool==5.3.1`. Проверка: `py -m esptool version` → `5.3.1`.
4. Драйвер CH340 (CH341SER) с сайта WCH. Проверка: Диспетчер устройств →
   «Порты (COM и LPT)» → «USB-SERIAL CH340 (COMx)», когда D1 mini подключена.

### 1.3. Как найти COM-порт платы

Номер порта меняется: на этом ноутбуке **COM3 и COM4 — Bluetooth**, плата
бывает COM5 или COM6 [измерено]. Любая D1 mini в том же гнезде USB получает тот
же номер, поэтому номер порта **не говорит, какая это плата**. Ищем порт по
коду производителя переходника CH340 — VID `1A86`:

```powershell
Get-CimInstance Win32_PnPEntity | Where-Object { $_.PNPDeviceID -like '*VID_1A86*' } | Select-Object Name
```

Должно быть: `USB-SERIAL CH340 (COM6)`. Пусто — плата не видна (кабель, драйвер,
питание). Есть клоны D1 mini на CP2102 (VID `10C4`): их видит `kakoy_kart.py`, а
`usb_log.py` ищет только CH340 — ему тогда порт указывать вручную (`--port`).

### 1.4. Частые ошибки

| Что видно | Причина | Что делать |
|---|---|---|
| `python` открывает Microsoft Store или «не найден» | в оболочке приложения Claude `python` указывает на заглушку Windows | писать `py` |
| порт не появляется | кабель только для зарядки; нет драйвера; у платы нет питания | другой кабель; поставить драйвер; при кабеле с изолентой — включить карт |
| `could not open port` / `PermissionError(13, 'Отказано в доступе')` | порт держит другая программа: `usb_log.py`, `Какой карт.bat`, монитор порта | закрыть её |
| `.bat` с русскими строками падает с «'т' is not recognized» | `cmd` ломается на кириллице после `chcp 65001` | новые ярлыки писать только латиницей (как `Какой карт.bat` и `USB лог.bat` внутри) |

## 2. Как узнать, какой это карт (`Какой карт.bat`)

**Зачем.** На плате номер карта не написан. Все платы прошиты одним образом и
называют себя одинаково (`Kart_4_`). Различает их только **DUUID** — номер чипа
ESP8266 (он же последние 3 байта MAC). Скрипт читает DUUID по USB и находит номер
на кузове в `karts.conf`.

**Что нужно.** Ноутбук (раздел 1), кабель microUSB с данными, файл `karts.conf`
рядом со скриптом в `kart-marshal\`. Свежая копия — с кассы
(`C:\FireDrift-тест\marshal\karts.conf`) или из FireDrift_Access.

**Шаги.**

1. Карт не в заезде, лучше выключен. **При чтении D1 mini перезагружается**
   (esptool переводит её в режим загрузчика) — карт на заезде не подключать.
2. Двойной щелчок `Какой карт.bat` в папке `kart-marshal`. Скрипт пишет
   `Номера из …\karts.conf от <дата>, картов: N` и `Втыкайте D1 mini в USB`.
3. Посмотреть на дату файла. Старая — номера могут быть неверны (на ноутбуке
   лежит копия от 12.09, а на кассе файл менялся 25.11). Сверять с
   `ai/09-karty.md`.
4. Воткнуть кабель в D1 mini. Через 1–3 с:

   ```
     COM6   MAC …   DUUID 12345678
     ============================
           ЭТО КАРТ №7
     ============================
     Можно вынимать.
   ```

   или `Этого DUUID в karts.conf нет: новый или запасной модуль. Номер на кузове
   ему вписывают в админке.`
5. Вынуть кабель → `Вынули. Жду следующую плату.` Следующая плата. Выход — Ctrl+C.

Из консоли: `py kakoy_kart.py --port COM6` — прочитать одну плату и выйти;
`--conf <путь>` — номера из другого файла.

**Что должно получиться.** DUUID и номер карта.

**Частые ошибки.**

- MAC в выводе — не переписывать в чаты и файлы.
- `не прочитал — Could not open port` — порт занят (раздел 1.4).
- `No serial data received` — у платы нет питания, плохой кабель или плата
  мертва (02.11 запасная плата так и не ответила [измерено]).
- Без USB: в панели дать тест-драйв на 1 мин одной карточке и посмотреть, у
  какого карта загорелся дисплей (`docs/montazh.md`, раздел 3). Только без гостей
  и с картами на месте: при тест-драйве реле включено.

## 3. Прошивка платы

**Зачем.** Новая D1 mini (пустая или с чужой прошивкой); плата жива
(`config.live.json` отвечает), но не звонит на кассу; испорчены файлы или Wi-Fi
платы; сменился адрес кассы. Код прошивки мы не меняем — только адрес сервера в
образе. Шить — по решению владельца.

### 3.1. Какой образ

Оба образа — только в закрытом репозитории FireDrift_Access (папка
`proshivka/`): внутри пароль Wi-Fi картов.

| Образ | Что это | Когда |
|---|---|---|
| заводской дамп (`kart_dump.bin`) | флеш, снятый с карта 4, с адресом сервера производителя | для разбора и как исходник для патча. На карт **не шить**: плата будет звонить не на кассу |
| образ с адресом кассы (`kart_192.168.1.50.bin`, 4 МБ) | тот же дамп, адрес сервера заменён на `192.168.1.50` | его шьют на карты. Все карты работают на нём [измерено] |

В той же папке может лежать другая сборка (`kart_192.168.1.50_60min.bin`) — не
путать; что в ней, **[не проверено]**.

### 3.2. Карта флеша и два способа прошивки

Флеш 4 МБ [разбор прошивки, `ai/03-proshivka.md`]:

| Адрес | Что |
|---|---|
| `0x000000` | загрузчик |
| `0x001000` | программа (с адресом сервера) |
| `0x180000` | копия программы для обновления по сети |
| `0x200000` | файловая система: `config.json` (имя `Kart_4_`, Wi-Fi, `maxSpeed` 70), `raceslist.txt`, `localdrives.json`, `reboots.json` |
| `0x3FB000` | EEPROM, пусто |
| `0x3FC000` | настройки Wi-Fi и радио SDK |

| Способ | Что пишется | Что плата теряет | Когда |
|---|---|---|---|
| **Полный образ** с `0x0`, 4 МБ, перед этим `erase-flash` | всё | свои файлы и свои настройки Wi-Fi: получит те, что были в образе при снятии дампа | новая или пустая D1 mini; испорчены файлы или Wi-Fi платы |
| **Только программа**: первые 1 МБ (`0x000000–0x0FFFFF`), без `erase-flash` | загрузчик и программа | ничего: файлы и Wi-Fi платы остаются | плата в порядке, нужна только программа или новый адрес сервера; Wi-Fi в плате менять нельзя (например, пароль Wi-Fi сменили после снятия дампа) |

Способ «только программа» выведен из карты флеша; на живой плате так шили или
нет — **[не проверено]**. Первый раз — на одной плате, на подставке.

### 3.3. Полный образ — шаги

**Что нужно:** ноутбук (раздел 1), обычный кабель microUSB с данными (не с
изолентой), образ из FireDrift_Access, ~10 минут.

1. Карт выключить, **снять батарею**.
2. Закрыть всё, что держит порт: `usb_log.py`, `Какой карт.bat`, мониторы порта.
3. Воткнуть кабель в D1 mini, найти COM (раздел 1.3). Ниже — `COM6`, подставить
   свой.
4. Записать, какая это плата:

   ```powershell
   py -m esptool --port COM6 chip-id
   ```

   В выводе `Chip ID: 0x…` — это DUUID в шестнадцатеричном виде.
5. По желанию — снять копию того, что сейчас во флеше (если плата «странная» и её
   хотят разобрать). Внутри будет пароль Wi-Fi: хранить только в FireDrift_Access.

   ```powershell
   py -m esptool --port COM6 --baud 460800 read-flash 0 0x400000 backup-плата.bin
   ```

6. Стереть флеш:

   ```powershell
   py -m esptool --port COM6 erase-flash
   ```

   Должно быть `Flash memory erased successfully`.
7. Записать образ:

   ```powershell
   py -m esptool --port COM6 --baud 460800 write-flash 0x0 kart_192.168.1.50.bin
   ```

   На 460800 срывается — убрать `--baud 460800` (115200, около трёх минут). На
   длинных и дешёвых кабелях высокая скорость не держится.
8. **Успех — две строки в конце:** `Wrote 4194304 bytes … at 0x00000000` и
   `Hash of data verified.` Второй строки нет — лить заново, плату не ставить.

### 3.4. Только программа — шаги

Шаги 1–4 те же. Потом:

5. Один раз сделать из полного образа файл с первыми 1 МБ:

   ```powershell
   py -c "d=open('kart_192.168.1.50.bin','rb').read(); open('kart_app_1M.bin','wb').write(d[:0x100000])"
   ```

   ```powershell
   (Get-Item kart_app_1M.bin).Length
   ```

   Должно быть `1048576`.
6. **Без `erase-flash`** (он стёр бы и файлы, и Wi-Fi):

   ```powershell
   py -m esptool --port COM6 write-flash 0x0 kart_app_1M.bin
   ```

7. Успех: `Wrote 1048576 bytes …` и `Hash of data verified.`

### 3.5. Проверка после прошивки

1. Вынуть USB, вернуть батарею, карт на подставку, включить.
2. За 10–20 с плата входит в Wi-Fi и звонит на кассу. В логе маршала:
   `карт подключился (192.168.1.x:…)`, затем `опознан, имя: N` (или `—`, если
   номера нет). В панели появляется карточка «свободен».
3. В «Живых полях» админки: `kOn=0`, `kOn1=1` (маршал разоружает свободный карт и
   зажигает свет), `uptime` маленький, `rssi` −50…−65.
4. Тест-драйв на 1 мин на подставке: `kOn=1`; педаль отпущена — `adcIn` 40–49, в
   пол — 180–189; `adc0` растёт с педалью; после «Стоп» — `kOn=0`
   (`ai/07-izmereniya.md`).
5. **Новая D1 mini (новый DUUID):** в админке «Имена картов» вписать номер,
   задать «Скорость по картам» и «Докатку по картам» (иначе общие значения),
   записать DUUID ↔ номер в FireDrift_Access и `ai/09-karty.md`. Резервацию
   адреса в Keenetic — по решению владельца (`ai/05-set.md`, 2.3).
6. После полного образа плата зовётся `Kart_4_` и хранит `maxSpeed` 70 — это
   нормально: файловая система идёт в образе целиком, а номер карта маршал берёт
   из `karts.conf` по DUUID.

**Если плата не появилась:**

| Что видно | Что значит |
|---|---|
| нет в списке Keenetic | не вошла в Wi-Fi: в образе старые имя или пароль Wi-Fi (полный образ кладёт те, что были при снятии дампа), антенна, питание. Может поднять свою точку `ktWiFi` — поискать телефоном [не проверено для этой прошивки] |
| в Keenetic есть, `config.live.json` отвечает, в логе маршала нет | плата не звонит на кассу: залит заводской дамп вместо образа кассы, или у кассы не `.50`, или закрыт порт 8080 |
| USB-лог показывает загрузку по кругу; в ARP два IP на один MAC | перезагрузки: дорожка I2C к U3 или питание (`docs/montazh.md`, `ai/08-diagnostika.md`) |

### 3.6. Замена адреса сервера в образе (для разработчика)

Нужна, только если у кассы сменится адрес (тогда перешивать **все** карты) или
если делается новый образ. Решение — владельца.

- Адрес лежит строками по смещениям `0x7f847` (поле на 13 символов) и `0x7f855`
  (на 15), копии в части для обновления — `0x1fe847` и `0x1fe855` [разбор
  прошивки; `docs/protokol.md`]. В нашем образе оба поля — адрес кассы.
- **Порт 8080 — число в коде**, строкой не меняется.
- Новый адрес не длиннее поля; остаток поля — нулевые байты; ничего не сдвигать:
  размер файла остаётся 4 194 304 байта.
- Нужна ли после замены правка контрольной суммы программы — **[не проверено]**.
  По `docs/protokol.md` образ кассы получен именно заменой этих строк и работает
  на всех картах.

Набросок скрипта (на образе **не запускался** — сначала посмотреть, что он
напечатает в режиме «только показать»). Пишет **новый** файл, исходник не трогает:

```python
# addr_patch.py
#   py addr_patch.py <образ.bin>                       показать поля
#   py addr_patch.py <образ.bin> <новый.bin> <адрес>   записать новый файл
import sys
FIELDS = [(0x7f847, 13), (0x7f855, 15), (0x1fe847, 13), (0x1fe855, 15)]
data = bytearray(open(sys.argv[1], "rb").read())
assert len(data) == 0x400000, "ожидался полный образ 4 МБ"
for off, size in FIELDS:
    print(hex(off), bytes(data[off:off + size + 1]))
if len(sys.argv) == 4:
    new = sys.argv[3].encode("ascii")
    for off, size in FIELDS:
        assert len(new) <= size, "адрес длиннее поля"
        data[off:off + size] = new + b"\0" * (size - len(new))
    open(sys.argv[2], "wb").write(data)
    print("записан", sys.argv[2])
```

В режиме «показать» в каждой строке должен быть адрес и ноль после него. Что-то
другое — смещения не те, ничего не писать.

Проверка нового образа — `analyze_dump.py`, но **только раздел адресов**: скрипт
печатает на экран и настройки Wi-Fi с паролем.

```powershell
py analyze_dump.py kart_новый.bin | Select-String '@ 0x'
```

Должен быть новый адрес на смещениях `0x07F847` и т. д., старого — нет. Рядом с
образом появятся `all_strings.txt` и `report.txt` с паролем — удалить их сразу.
Первую плату — на подставке, по разделу 3.5.

### 3.7. Частые ошибки при прошивке

- Запись с `0x1000` вместо `0x0` — загрузчик пустой, чип молчит намертво.
- Браузерный esptool-js — `Invalid head of packet`. Только Python esptool,
  команды через дефис (`write-flash`, `erase-flash`).
- Порт занят или выбран Bluetooth (COM3/COM4).
- Нет строки `Hash of data verified.` — лить заново.
- Залит заводской дамп вместо образа кассы — плата в Wi-Fi есть, а в маршале нет.
- `erase-flash` перед «только программой» — плата потеряла свой Wi-Fi.

## 4. USB-лог платы (`usb_log.py`, `USB лог.bat`)

**Зачем.** Увидеть, что плата печатает сама: загрузку, подключение к кассе,
команды маршала, сообщения прошивки (таймаут ожидания 600 с, местный режим,
парковка, катание), падения программы (`Exception`, `Soft WDT`), перезагрузки и
пропадание питания. Главное применение — найти, почему плата перезагружается или
рвёт связь.

**Что нужно.**

- Ноутбук (раздел 1). **Работает от батареи, без зарядки** [владелец]: ноутбук
  соединяется с картом, сеть 220 В туда не тянуть. Перед долгим логом проверить
  заряд.
- **Кабель USB с изолентой на контакте +5 В (VBUS) штекера USB-A** (раздел 4.1).
- Карт на подставке, колёса в воздухе: плата снизу или под сиденьем, на ходу
  ноутбук не подключить [владелец].
- Для причины перезагрузки — второй переходник USB-TTL (раздел 4.5), по желанию.

### 4.1. Кабель с изолентой — обязательный приём

На штекере USB-A четыре контакта: два крайних длиннее — это +5 В (VBUS) и минус,
два средних — данные. Заклеить тонкой полоской изоленты **контакт +5 В**.

Что это даёт:

- плата и её чип USB (CH340) питаются **только от карта**, не от ноутбука;
- порт появляется, только когда карт включён;
- **«порт пропал» в логе = у платы пропало питание** (замок, разъём, провал);
- без изоленты USB подпитывает плату, и провалы питания карта не видны; заодно
  плата долго получает 5 В с двух сторон.

**Проверка кабеля (обязательно перед первым логом):**

1. Карт выключен. Кабель с изолентой — в ноутбук и в D1 mini. **Порта нет**
   (раздел 1.3 пусто), синий светодиод D1 mini не горит. Порт есть — заклеен не
   тот контакт или изолента не держит.
2. Включить карт: порт появился, лог пишется. Порта нет и при включённом карте —
   скорее всего заклеен минус, а не +5 В.

С изолентой порт есть при включённом карте — проверено на одной D1 mini
[измерено 25.11]; на других платах — **[не проверено]**.

### 4.2. Запуск

1. Кабель с изолентой — в ноутбук и в D1 mini.
2. Двойной щелчок `USB лог.bat` в `kart-marshal`. На вопрос `Kart number:` ввести
   номер карта (цифрами) и Enter. Пустой ответ — скрипт упадёт с ошибкой
   аргумента; ввести хоть что-то (`zapas`).
3. Скрипт пишет `[USB] жду плату по USB (CH340); ноутбук не уснёт, пока идёт лог`.
4. Включить карт. Через 1–2 с: `[USB] порт COM6 открыт, 115200 бод`, дальше
   строки платы.
5. Остановить — Ctrl+C (`[USB] остановлено`).

Из консоли: `py usb_log.py --kart 12`, ещё `--port COM6` (порт вручную),
`--rom-port COM7` (второй переходник), `--baud`, `--out <папка>`.

**Как устроено:**

- Порт открывается **без сигналов DTR/RTS**, поэтому плата **не перезагружается**
  при подключении (в отличие от esptool и `Какой карт.bat`).
- Порт ищется сам — первый CH340 (VID `1A86`). Пропал — скрипт каждую секунду
  пробует открыть снова.
- Файл: `kart-marshal\logs\usb\<карт>-<ГГГГ-ММ-ДД>.log`, дописывается, новый
  каждый день. Время строк — **с ноутбука**, до миллисекунд.
- Пока скрипт работает, Windows не уходит в сон; экран гаснуть может. **Крышку
  не закрывать** — ноутбук уснёт всё равно.
- Первые 1–2 с после включения карта в лог не попадают: Windows ещё не увидела
  порт.
- **При загрузке плата печатает свой `config.json` с паролем Wi-Fi.** Лог не
  пересылать целиком; вставляя строки в чат, эту строку вырезать. Папка `logs\`
  в git не попадает.

### 4.3. Что в логе

Формат строки: `ЧЧ:ММ:СС.мс  [МЕТКА]  текст`. Метки ставит скрипт:

| Метка | По какой строке | Что значит |
|---|---|---|
| `[USB]` | сообщения самого скрипта | жду плату; порт открыт; **порт пропал** (с изолентой — пропало питание платы); остановлено |
| `[СВЯЗЬ]` | `[WSc] Connected` | вебсокет к кассе поднялся |
| `[ОБРЫВ]` | `[WSc] Disconnected` | вебсокет оборвался |
| `[ЗАГРУЗКА]` | `Start FS` | плата загружается (начало программы) |
| `[СБОЙ]` | `Exception`, `Soft WDT`, `wdt reset`, `>>>stack>>>` | программа упала — отчёт ядра перед перезагрузкой |
| `[СБРОС]` | `rst cause` | причина сброса прочиталась текстом (на 115200 редко) |
| `[ПЕРЕЗАГРУЗКА]` | строка-мусор | загрузчик ESP печатает на 74880, на 115200 это мусор — признак перезагрузки |
| `[ТАЙМАУТ 600 С]` | «время ожидания» | «закончилось время ожидания катания»: плата сама сняла реле через 600 с после последнего `Start` |
| `[МЕСТНЫЙ РЕЖИМ]` | «локальн» | местный режим взведён, начат или снят |
| `[ПАРКОВКА]` | «время парковки» | после катания по I/O — минута на 20% |
| `[КАТАНИЕ]` | «время катания» | катание по I/O началось или закончилось |
| `[12 Ч БЕЗ СВЯЗИ]` | «Связь отсутствует» | 12 часов без связи — плата перезапускается сама |
| `[ПРИЧИНА]` | второй переходник | `rst cause:N` с расшифровкой (раздел 4.5) |

Строки без метки — обычная работа:

- `[WSc] get text: {"Command": "Status"}` — команда маршала (опрос раз в ~6 с;
  так же видны `Start`, `Stop`);
- `[WSc] get pong DriveON: 0 timeDriveOn: 0 timeParking: 0 localModeStart: 0
  llocalModeWaitStart: 0 WiFi.Connected: 1` — раз в ~15 с, состояние заезда на
  плате;
- шаги загрузки (`Start WIFI`, …), `Sen ok = TIMEOUT` (нет датчика температуры —
  норма).

Русские сообщения прошивки — в UTF-8, скрипт читает их как текст. **До ~18:04
25.11** скрипт принимал их за мусор, и в логах до этого времени `[ПЕРЕЗАГРУЗКА]`
может быть ложной [измерено: №15 18:03:25 — «мусор», а через 1 с плата
продолжила отвечать].

**Чего в USB-логе нет:** значений педали и АЦП (`adcIn`, `adc0` и т. д.) — плата
их в USB не печатает, они в телеметрии маршала (`ai/10-zhurnaly.md`). Причины
сброса без второго переходника.

Пример (№15, 25.11, без секретов):

```
17:07:05.854  [USB]        жду плату по USB (CH340); ноутбук не уснёт, пока идёт лог
17:07:14.961  [USB]        порт COM6 открыт, 115200 бод
17:07:23.273  [СВЯЗЬ]      [WSc] Connected to url: /
17:07:23.780               [WSc] get text: {"Command": "Status"}
17:07:23.782               [WSc] get pong DriveON: 0 timeDriveOn: 0 timeParking: 0 localModeStart: 0 llocalModeWaitStart: 0 WiFi.Connected: 1
17:42:22.568  [USB]        порт COM6 пропал: GetOverlappedResult failed (PermissionError(13, 'Отказано в доступе.', None, 5))
```

### 4.4. Как читать

| Что видно | Что это |
|---|---|
| `порт … пропал`, потом `порт … открыт` и строки загрузки | у платы пропадало питание (кабель с изолентой) |
| `[ПЕРЕЗАГРУЗКА]`, затем в течение ~10 с `[ЗАГРУЗКА]` … `[СВЯЗЬ]` | плата перезагрузилась, питание при этом было (порт не пропадал) |
| `[ПЕРЕЗАГРУЗКА]`, а через секунду снова `get pong` | не перезагрузка (старый лог до 18:04 25.11 или помеха) |
| `[СБОЙ]` перед перезагрузкой | упала программа; строки отчёта сохранить для разбора |
| `[ОБРЫВ]` без перезагрузки | плата сама потеряла вебсокет; сравнить со строкой `карт отключился` в логе маршала |
| `[ТАЙМАУТ 600 С]` | маршал не продлил кусок вовремя — искать в логе маршала продление этого карта |

**Время.** Часы ноутбука и кассы могут расходиться. Сдвиг находят по общему
событию: `WS out <DUUID> {"Command": "Start", …}` в логе маршала и
`[WSc] get text: {"Command": "Start", …}` в USB-логе; или `карт отключился` и
`[ОБРЫВ]`. Собственные часы платы отстают от местных на 1 час (в прошивке зашит
пояс Самары, UTC+4) [измерено 25.11] — это касается её внутренних записей, а не
времени строк USB-лога.

### 4.5. Причина перезагрузки: второй переходник

Загрузчик ESP8266 при каждом сбросе печатает строку вида
`ets Jan  8 2013,rst cause:2, boot mode:(3,6)` на скорости 74880. На 115200 она
приходит мусором, и надёжно её оттуда не расшифровать (проверено 25.11: отрыв в
один бит).

**Что нужно:** второй переходник USB-TTL с логикой 3,3 В и два провода.

1. Карт выключен, батарея снята.
2. **RX переходника — на пин TX платы** (D1 mini, пин `TX`), **GND переходника —
   на `G`**. TX переходника никуда не подключать.
3. Оба кабеля в ноутбук. Найти оба COM (раздел 1.3).
4. Запуск с явными портами (оба могут быть CH340):

   ```powershell
   py usb_log.py --kart 12 --port COM6 --rom-port COM7
   ```

5. При каждом сбросе в логе: `[ПРИЧИНА] ets Jan 8 2013,rst cause:N, … — <расшифровка>`.

| Код | Причина |
|---|---|
| 1 | включение или провал питания |
| 2 | ножка RST (кнопка, помеха) или программный перезапуск |
| 4 | аппаратный сторожевой таймер — программа зависла |
| другой | `другая (N)` |

`docs/montazh.md` и старые записи пишут «1 или 2 — питание или наводка»; по коду
`usb_log.py` и разбору прошивки 2 — ножка RST или программный перезапуск.
Не мешает ли второй переходник на TX работе платы — **[не проверено]**.

### 4.6. Частые ошибки

- Кабель без изоленты: провалы питания не видны.
- Заклеен не тот контакт: порта нет и при включённом карте.
- Одновременно запущен `Какой карт.bat` или esptool — они перезагружают плату и
  занимают порт.
- Крышка ноутбука закрыта или подключена зарядка.
- Строку `config.json` с паролем вставили в чат.

## 5. Чтение живых полей

**Зачем.** Видеть, что происходит с платой сейчас: реле (`kOn`), свет (`kOn1`),
педаль (`adcIn`), газ на контроллер (`adc0`), I/O (`dIn`), напряжение (`aIn`),
сигнал (`rssi`), перезагрузки (`uptime`). Что значит каждое поле и нормы —
`ai/07-izmereniya.md`.

### 5.1. Прямо с платы

Без пароля, с кассы или с ноутбука в Wi-Fi картов. IP платы — `ai/05-set.md`,
раздел 5.

```powershell
curl.exe --noproxy "*" http://192.168.1.x/config.live.json
```

В ответе JSON, среди прочего `kOn`, `kOn1`, `adcIn`, `adc0`, `adc3`, `aIn`, `dIn`,
`uptime`, `rssi`, `DUUID` [измерено 02.11]. `--noproxy "*"` — чтобы запрос не ушёл
в системный прокси.

Следить за полями раз в 3 с (Ctrl+C — стоп):

```powershell
while ($true) { $j = curl.exe -s --noproxy "*" http://192.168.1.x/config.live.json | ConvertFrom-Json; "{0:HH:mm:ss} kOn={1} kOn1={2} adcIn={3} adc0={4} aIn={5} dIn={6}" -f (Get-Date), $j.kOn, $j.kOn1, $j.adcIn, $j.adc0, $j.aIn, $j.dIn; Start-Sleep 3 }
```

**Не чаще раза в 2–3 с и по возможности не во время заездов с гостями:** пока
плата отвечает на HTTP, её вебсокет стоит [разбор прошивки]. Маршал по той же
причине шлёт платам HTTP строго по одному.

### 5.2. Через админку

`http://localhost:8080/admin` на кассе (вход — человек, пароль в
FireDrift_Access) → блок «Живые поля» → выбрать карт. Все поля плиткой;
изменившееся поле на секунду подсвечивается. Телеметрия у маршала меняется раз в
6 с (опрос). Удобно: «нажми педаль и смотри, какое поле дёрнулось».

### 5.3. По журналу маршала

Каждые 6 с строка `WS in <DUUID>  Status  driveOn=… kOn=… adcIn=…` — история
полей за любое время (`ai/10-zhurnaly.md`). Нет полей вне списка маршала
(полный JSON в лог не пишется).

## 6. Ручные команды плате через админку

**Зачем.** Проверить реле, свет, лимит или ответ платы в обход заезда — на
подставке, при наладке.

**Главное:** ручная команда **не создаёт заезда на сервере**. Маршал о ней не
знает: не продлевает, не делает докатку, не закрывает. Для проверки «едет ли
карт» почти всегда лучше **тест-драйв из панели** на 1 мин: маршал сделает всё сам
и закроет.

### 6.1. Что делает каждая команда

| Команда (где в админке) | Что делает | Когда безопасно | Что сделать после |
|---|---|---|---|
| `Status` (вебсокет) | плата присылает телеметрию | всегда | — |
| `Start`, Length N (вебсокет) | плата начинает свой заезд в ожидании I/O, зажигает свет; реле **не** включает [разбор прошивки]. С включённым реле карт поедет; плата сама снимет реле через 600 с (или Length + 60 с после щелчка I/O) | только на подставке, никто не сидит, карт свободен | `Stop`, проверить `kOn=0` |
| `Stop` (вебсокет) | реле и свет выключаются, плата занята ~1 с, лимит возвращается к `maxSpeed` из её `config.json` [разбор прошивки] | у свободного карта — всегда. **Не вместо «Стоп» в панели**: заезд на сервере останется, и следующее продление снова включит реле | — |
| `MaxSpeed` + «Применить» (вебсокет) | шлёт поле `MaxSpeed`; плата, по разбору прошивки, читает `Speed` — результат **[не проверено]** | на подставке | лимит ставить по HTTP |
| «Отправить как есть» | любой JSON; регистр важен | только зная, что шлёшь | — |
| `On6` (HTTP) | **реле включено: карт едет от педали** | только на подставке, никто не сидит | `Off6` и `kOn=0`. Сам маршал свободному карту реле не снимет (только при переподключении); через 10 с карточка станет «едет сам» |
| `Off6` (HTTP) | реле выключено — настоящий тормоз | у свободного карта — всегда. У карта в заезде — карт встанет до следующего продления, которое реле вернёт: для заезда — «Стоп» в панели | — |
| `On7` / `Off7` (HTTP) | только свет; следующая команда заезда его перебьёт | всегда | — |
| `maxSpeed` 0..100 (HTTP) | лимит до следующего `Start`/`Stop`/продления. Пишет ли во флеш — **[не проверено]** | на подставке | — |
| часовой пояс (HTTP `timeZone`) | пишет пояс платы. Перебивает ли зашитый пояс Самары — **[не проверено]** | по решению владельца | — |
| «Перезагрузить плату» (HTTP `restart`) | плата пропадёт ~20 с и подключится сама; в заезде карт встанет, маршал вернёт заезд | без гостя на карте | дождаться `опознан` в логе |

**Список «команды для» по умолчанию — «всех картов».** Без выбора карта `Start`
или `Stop` уйдут **всем картам на связи**. Перед любой командой — выбрать карт.

Чего не делать никогда: дёргать сеттеры платы без параметров (`/ssid`, `/ssdp` и
др. через `/api/admin/http`) — это записывает пустые значения и ломает
настройки платы (так стирали имя устройства). Смена Wi-Fi платы — только по
решению владельца (`ai/05-set.md`, 2.5). Запросы — по одному, не спамить: ESP8266
от пачек перезагружается.

### 6.2. Проверка реле на подставке — шаги

1. Карт на подставке, колёса в воздухе, никто не сидит; в панели «свободен».
2. Админка → «Живые поля» → этот карт: `kOn=0`, `kOn1=1`, `adcIn` около 0–3
   (у №15 около 45: педаль питается мимо реле [измерено]).
3. «Прямой HTTP к плате» → выбрать карт (IP подставится) → `On6`. В «Логе обмена»
   `← 200 (N мс)`. Через ≤ 6 с в «Живых полях» `kOn=1`, `adcIn` 40–49.
4. Нажать педаль: `adcIn` 180–189, `adc0` растёт; колесо крутится.
5. `Off6` → `kOn=0`. Колесо остановилось.
6. Не стало `kOn=0` — ещё раз `Off6`; не помогает — выключить карт и разбирать
   (`ai/08-diagnostika.md`).

### 6.3. Аварийно, когда маршал лежит

Снять реле прямо с ноутбука в Wi-Fi картов:
`curl.exe --noproxy "*" -u <логин>:<пароль> http://<IP>/Off6` (заводской логин
веб-морды — FireDrift_Access, вводит человек). Останавливает ли это карт без
сервера и нужен ли логин для `/Off6` — **[не проверено]** (`docs/voprosy.md`,
вопрос 4). Надёжный способ — выключить карт.

## 7. Выкатка маршала на кассу

**Зачем.** Поставить на кассу новую версию `marshal.py` (и `panel.html`,
`admin.html`, если менялись).

**Как устроено.** Ветка `kassa-sync-reconnect` в GitHub
(`zionist-cmd/FireDrift_Marshall`) — то, что стоит на кассе. На кассе git нет:
правки идут через PR в эту ветку (без git — в веб-редакторе GitHub), а на кассу
файл приходит скачиванием с GitHub и **проверкой SHA-256**. Перезапуск — только
между группами, время выбирает владелец.

**Что нужно:** номер коммита и эталонный SHA-256 от того, кто готовил версию;
доступ к PowerShell на кассе; окно между группами.

### 7.1. Подготовка (у разработчика)

1. Тесты прошли (раздел 8.1), сценарий проверен на поддельных картах (8.2).
2. Изменения слиты в `kassa-sync-reconnect`. Запомнить номер коммита.
3. **Эталонный SHA-256 считать с файла, как он лежит на GitHub**, а не с рабочей
   копии на Windows: с `core.autocrlf=true` рабочая копия с CRLF, и её хеш другой
   [измерено 25.11: хеш рабочей копии не совпал с хешем файла в git]. Проще всего
   скачать файл той же ссылкой, что и касса (шаг 7.2.1), и посчитать
   `Get-FileHash`.

### 7.2. На кассе, заранее (можно во время работы)

1. Скачать в папку подготовки, **не в `marshal\`**. В ссылке — номер коммита, а не
   имя ветки (по имени ветки GitHub несколько минут может отдавать старую копию):

   ```powershell
   New-Item -ItemType Directory C:\FireDrift-тест\marshal-stage-20261126
   ```

   ```powershell
   curl.exe -L -o C:\FireDrift-тест\marshal-stage-20261126\marshal.py https://raw.githubusercontent.com/zionist-cmd/FireDrift_Marshall/<коммит>/marshal.py
   ```

2. Сверить хеш:


## 8. Проверки маршала без железа

### 8.1. Автотесты

**Где:** на ноутбуке, в папке `kart-marshal`. Не на кассе.

```powershell
py -m unittest discover tests
```

Должно быть: `Ran 69 tests in 0.3s` и `OK` [измерено 25.11, версия 8790002,
Python 3.15.2]. Число тестов растёт с версиями; главное — `OK` и ни одного `FAIL`
или `ERROR`.

Что проверяют: защиту (255, местный режим), закрытие заезда без гонок, продление
без Stop и откат на Stop, перевзвод после щелчка I/O, скорость по градациям,
запись и чтение `karts.conf`.

Тонкости:

- Тесты загружают `marshal.py` по пути (в стандартном Python есть свой модуль
  `marshal`). При загрузке читаются `marshal.conf` и `karts.conf` рядом; **если
  `marshal.conf` нет, он создаётся** со случайным паролем админки.
- Настоящие `karts.conf` и `rides-state.json` тесты не пишут: подменяют пути и
  запись.

### 8.2. Поддельные карты (`fakekart.py`)

**Зачем:** проверить маршал и панели целиком, как с живыми картами.

**Шаги.**

1. Ноутбук **не** должен быть в сети картов с адресом `.50` (обычно и не бывает).
   **Никогда не направлять `fakekart.py` на кассу** (`--host 192.168.1.50`):
   поддельные карты появятся в настоящей панели.
2. Окно 1 — маршал на ноутбуке:

   ```powershell
   py marshal.py
   ```

   Возьмёт локальные `marshal.conf` и `karts.conf`, будет писать `logs\` и
   `rides-state.json` в папку репозитория (в git они не попадают).
3. Браузер: `http://localhost:8080/` и `http://localhost:8080/admin`.
4. Окно 2 — поддельные карты, например `py fakekart.py`. DUUID с 90000001, чтобы
   не путать с настоящими.
5. Запускать заезды из панели и смотреть лог маршала и вывод `fakekart`.
6. Ctrl+C в обоих окнах.

У поддельных картов нет HTTP (адреса `10.20.0.x` никуда не ведут): строки
`НЕ ПРОШЛО`, `отложено` и `СДАЮСЬ` для них — норма, и очередь HTTP из-за таймаутов
идёт медленнее.

| Ключ | Что изображает | Что должен сделать маршал (строки лога) |
|---|---|---|
| без ключей | 3 исправных карта на `127.0.0.1:8080`, педаль отпущена | заезд: `заезд N мин, скорость «…» (L)`; у заезда 9+ мин на ~532 с `продление без Stop: кусок N с, лимит L` |
| `--karts N`, `--first D`, `--host`, `--port` | число картов, первый DUUID, адрес маршала | — |
| `--pedal` | педаль нажата (`adcIn` 180–189 при включённом реле) | перевзвод ждёт: `… педаль нажата (adcIn=N) — перевзведу, как только отпустят` |
| `--pedal-cycle` | педаль 7 с нажата, 5 с отпущена | перевзвод дождётся отпускания |
| `--local` | карт 1 подключается посреди местного катания без оплаты | `ЗАЩИТА: катается в местном режиме без оплаты … — останавливаю карт`; `fakekart`: `Stop — местное катание снято` |
| `--adc-fault` | у карта 1 при включённом реле все АЦП = 255 | после старта: `ЗАЩИТА: сбой платы: adcIn, adc0, adc3=255 … — останавливаю карт`, заезд закрыт, плашка в панели, новый старт отклоняется 10 мин: `карт неисправен — …` |
| `--wait N` | таймаут ожидания платы после `Start` (у прошивки 600 с) | меньше 540 — плата снимет реле раньше продления; видно, как маршал продлевает через `Stop` |
| `--io-edge` | на карте 1 гость щёлкает I/O на каждом `Start` | два перевзвода, затем `щелчок I/O снова после 2 перевзводов — больше не перевзвожу, продления через Stop` |
| `--io-edge-after N` | на карте 1 I/O включают один раз через N с после старта (как №13 25.11) | `щелчок I/O посреди заезда, педаль отпущена (adcIn=4x) — перевзвожу плату…`, `перевзвод после щелчка I/O: кусок …`, дальше `продление без Stop` |

Перевзвод и продления видны только в заезде длиннее 8 мин. Чтобы не ждать 9
минут, на ноутбуке можно уменьшить `chunk_seconds` в локальном `marshal.conf`
(например, 120) и перезапустить маршал; на кассе — никогда.
