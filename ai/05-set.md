# Сеть площадки: Keenetic, касса, MikroTik

Как связаны карты, касса и роутеры, как это проверить и починить, почему карты
отваливаются. Метки: **[измерено]** (журналы, замеры, с датой), **[владелец]**,
**[разбор прошивки]**, **[не проверено]**.

Пароли (Wi-Fi картов, вход в Keenetic), MAC-адреса и таблица адресов картов —
**только** в закрытом репозитории FireDrift_Access (`set.md`, `karty.md`). Сюда и в
чаты их не писать. Человек вводит пароли сам; агент их не набирает.

Связанные файлы: маршал — `ai/04-marshal.md`; процедуры и команды для платы —
`ai/06-instrumenty.md`; журналы и поиск по ним — `ai/10-zhurnaly.md`; симптом →
шаги — `ai/08-diagnostika.md`; карты по номерам — `ai/09-karty.md`.

---

## 0. Самое важное

1. **Карты звонят только на `192.168.1.50:8080`.** Адрес и порт зашиты в прошивку
   каждой платы [разбор прошивки]. Касса обязана иметь этот адрес в сети картов,
   иначе пропадут все карты разом. Сменить адрес в картах можно только
   перепрошивкой всех плат.
2. **Касса сидит в двух сетях двумя портами** (с 02.11 21:33): встроенный порт —
   сеть картов (`192.168.1.50`, вручную, **без шлюза**), USB-переходник — сеть
   DC/MikroTik (`192.168.88.64`). **Wi-Fi кассы выключен и включать его нельзя.**
3. **Keenetic и MikroTik не сбрасывать.** Сброс Keenetic — карты не попадут в
   Wi-Fi. MikroTik чужой (сеть ТЦ), пароля у клуба нет.
4. **Любые изменения Wi-Fi роутера** (пароль, шифрование, канал) роняют связь у
   всех картов — только с владельцем и без заездов.
5. **Кто в Wi-Fi картов, тот может управлять картами:** у плат нет настоящей
   авторизации. Пароль Wi-Fi — только персоналу; гостям — гостевая сеть.

## 1. Схема (с 02.11.2026)

```
Провайдер
 └─ MikroTik «DC», сеть 192.168.88.0/24 — сеть ТЦ, НЕ СБРАСЫВАТЬ, пароля у клуба нет
     ├─ игровые автоматы, терминал оплаты
     ├─ касса, USB-переходник «Ethernet 2» — 192.168.88.64, вручную, со шлюзом и DNS
     └─ Keenetic Skipper 4G KN-2910, порт 0 (синий) = WAN
          LAN 192.168.1.1/24 (порты 1–3), Wi-Fi картов 2,4 ГГц
           ├─ касса, встроенный порт «Ethernet» — 192.168.1.50/24, вручную, БЕЗ шлюза,
           │  кабель в LAN-порт Keenetic
           └─ карты 192.168.1.x — по Wi-Fi, адреса закреплены за MAC (резервации)
```

| Узел | Адрес | Что через него идёт |
|---|---|---|
| Keenetic | `192.168.1.1` | Wi-Fi картов, DHCP с резервациями, журнал роутера |
| касса, сеть картов | `192.168.1.50` | маршал: вебсокеты картов, панель, админка |
| касса, сеть DC | `192.168.88.64` | CRM: игровые автоматы, терминал, интернет |
| карты | `192.168.1.x` | каждая плата — вебсокет на `.50:8080`; HTTP-порт 80 для команд маршала |

Шлюз и DNS кассы в сети DC, WAN-адрес Keenetic, адреса автоматов и терминала —
FireDrift_Access, `set.md`.

## 2. Keenetic — сеть картов

### 2.1. Что это и как зайти

Keenetic Skipper 4G KN-2910: порт 0 (синий) — WAN в сеть DC, порты 1–3 — LAN,
Wi-Fi картов только 2,4 ГГц. Прошивка KeeneticOS 5.1.4, было доступно обновление
[измерено 28.10]. Обновлять — только с владельцем и после закрытия.

Веб-интерфейс: `http://192.168.1.1` с кассы или с устройства в Wi-Fi картов.
**Входит человек** (пароль — FireDrift_Access `set.md`); сессия живёт, пока
открыта вкладка. Встроенный браузер приложения Claude не смог открыть адрес
кассы `192.168.1.50` [измерено 02.11]; с роутером, скорее всего, так же
[не проверено] — смотреть просит человека.

Безопасно читать, когда человек уже вошёл (только чтение):

| Адрес | Что показывает |
|---|---|
| `http://192.168.1.1/rci/show/ip/hotspot` | кто сейчас в сети, сигнал (`rssi`), сколько держится связь |
| `http://192.168.1.1/rci/show/running-config` | весь конфиг. **Брать только строки `ip dhcp host`** (резервации): в остальном ключи и пароли, их не выводить |

Аптайм роутера (сколько он работает без перезагрузки) — на главной странице
интерфейса. 27.10 в 14:14 роутер перезагрузился, и все 10 картов отвалились за
7 мс [измерено по его аптайму и логам маршала].

### 2.2. Обязательные настройки Wi-Fi

| Параметр | Значение | Почему |
|---|---|---|
| Диапазон | только 2,4 ГГц | ESP8266 не видит 5 ГГц |
| Канал | **1, вручную** | автовыбор переезжает на другой канал и роняет всех разом |
| Ширина канала | **20 МГц** | 40 МГц в забитом эфире ТЦ собирает помехи |
| Шифрование | **WPA2-PSK** | в WPA3 платы не заходят |
| 802.11 r / k / v | **выключены** | роутер сам выгонял клиентов «уйти на другую точку», которой нет |
| Band Steering | выключен | |
| Изоляция клиентов | выключена | иначе карты не увидят кассу |
| Резервации DHCP | на каждый карт и на кассу `.50` | раздел 2.3 |

**802.11k/v — главный виновник обрывов в сентябре.** В журнале роутера это
строки `deauthenticated by AP (reason: due to BSS transition management)`. После
выключения обрывы упали с 1129 за два часа до 34 за три дня [измерено].

**Что нашли 28.10** [измерено по веб-интерфейсу]: канал 1 и 20 МГц — верно;
шифрование стояло **WPA2 + WPA3** вместо одного WPA2. Исправили ли, и выключены ли
сейчас 802.11k/v и Band Steering — **[не проверено]**. Переключение шифрования
переподключает Wi-Fi у всех примерно на минуту — только без заездов.

### 2.3. Резервации DHCP

- 28.10 адреса закреплены за MAC всех 15 картов и кассы (`.50`) [измерено по
  `running-config`]. Таблица «номер — DUUID — MAC — IP» — FireDrift_Access
  (`karty.md`, `set.md`).
- **Маршалу резервации не нужны:** он узнаёт карт по DUUID, а IP берёт из
  телеметрии. Резервации нужны людям: зная IP, проще читать плату напрямую.
- Имя платы в списке Keenetic — `ESP-XXXXXX`, где `XXXXXX` — DUUID в
  шестнадцатеричном виде (последние 3 байта MAC). У нескольких плат имя другое,
  заданное вручную.
- **Новая D1 mini — новый MAC.** Резервации у неё нет, она получит адрес из
  общего пула и всё равно будет работать. Закрепить адрес — решение владельца;
  после этого записать в FireDrift_Access.
- Резервация `.50` была сделана на MAC Wi-Fi кассы (28.10). Перевесили ли её на
  встроенный порт — **[не проверено]**. Касса держит `.50` вручную, поэтому для
  картов это не важно. Но если включить Wi-Fi кассы, он получит `.50` по
  резервации, и в сети будет два `.50` — это одна из причин не включать Wi-Fi.

### 2.4. Журнал роутера

Свой журнал Keenetic держит в памяти, недолго и до перезагрузки. Поэтому его
пересылают на кассу по syslog:

- **На кассе** работает приёмник `C:\FireDrift-тест\watch\keenetic-syslog.ps1`, он
  пишет `C:\FireDrift-тест\keenetic-logs\keenetic-<дата>.log` (с 01.11). Каждый
  день журнал жмётся в `logs-archive\keenetic-<дата>.zip` [измерено 25.11].
- У маршала есть свой приёмник: `syslog_port` в `marshal.conf` (строки роутера с
  меткой `RT` ложатся в лог маршала рядом с обрывами). На кассе журнал собирает
  `keenetic-syslog.ps1`; включён ли ещё и `syslog_port` — **[не проверено]**. Два
  приёмника на одном UDP-порту не уживутся: второй не откроет порт (маршал
  напишет `! журнал роутера: порт UDP … не открылся` и продолжит работать без
  него).

Как читать журнал роутера рядом с обрывом карта [измерено, разбор 21–25.11]:

| Что в журнале роутера | Что это значит |
|---|---|
| в секунду обрыва — тишина | Wi-Fi держался, оборвалось только соединение с кассой (плата сама закрыла вебсокет, кадр-мусор, касса) |
| сразу «deauth» и снова «associated» | плата перезагрузилась |
| через ~630 с после обрыва роутер выкидывает плату «за молчанием» | у платы пропало радио: карт выключили или пропало питание |
| `deauthenticated by AP (… BSS transition management)` | включены 802.11k/v — выключить |

Как найти строки конкретного карта — `ai/10-zhurnaly.md` (поиск по последним
байтам MAC, вычисленным из DUUID).

### 2.5. Чего с Keenetic не делать

- **Не сбрасывать.** Пропадут резервации; если сбросятся имя или пароль Wi-Fi
  или обязательные настройки (WPA3, 5 ГГц, 802.11k/v), карты не подключатся
  вообще. Имя и пароль Wi-Fi хранятся в каждой плате, поменять их удалённо можно
  только у платы, которая в сети. Останется вернуть роутеру прежние настройки
  или перешить все карты.
- **Не менять пароль Wi-Fi «просто так».** Порядок смены — сначала обойти все
  платы командой `/ssid?ssid=…&password=…` (каждую, пока она в сети), потом
  менять на роутере. Наоборот — карты отвалятся и вернутся только перепрошивкой
  (`docs/bezopasnost.md`). В админке кнопки смены Wi-Fi нет намеренно.
- **Не пускать в Wi-Fi картов посторонних.** 28.10 там сидел чужой телефон
  [измерено]. Кто в этой сети, тот может включить реле любому карту.
- Держать наготове (у владельца): выгрузку конфигурации Keenetic, таблицу
  «номер — DUUID — MAC — IP», копию `karts.conf`.

## 3. Касса: два сетевых порта

### 3.1. Как должно быть

| Адаптер Windows | Куда кабель | Адрес | Шлюз | Зачем |
|---|---|---|---|---|
| «Ethernet» (встроенный порт) | LAN-порт Keenetic | `192.168.1.50/24`, **вручную** | **нет** | сеть картов: маршал |
| «Ethernet 2» (USB-переходник) | сеть DC/MikroTik | `192.168.88.64/24`, вручную | шлюз и DNS DC (`set.md`) | CRM: автоматы, терминал оплаты, интернет |
| Wi-Fi | — | — | — | **выключен** |

- **Без шлюза в сети картов** — чтобы интернет, терминал и автоматы шли только
  через DC, а не пытались через Keenetic.
- **`.50` вручную, а не по DHCP** — адрес не зависит от роутера и его резерваций.
- **Wi-Fi выключен:** на Wi-Fi касса теряла связь с картами (0,7 обрыва в час
  против ~0,015 на кабеле [измерено]) и сама перескакивала в Wi-Fi «DC» с
  сообщением «Сеть отключена драйвером» [измерено 24.10]. Плюс риск двух `.50`
  (раздел 2.3).
- В брандмауэре Windows должен быть открыт входящий TCP 8080 из `192.168.1.0/24`
  для всех профилей (сеть без шлюза Windows считает «неопознанной»). Как точно
  называется правило на кассе — **[не проверено]**; что порт открыт, видно по
  тому, что карты подключаются.

### 3.2. История

| Когда | Что |
|---|---|
| до 29.10 | касса в сети картов по Wi-Fi (`.50`), встроенный порт — в DC |
| 29.10 | сеть картов переведена на кабель через USB-переходник |
| 30.10, 31.10 | USB-переходник дважды сам выпадал с шины USB. 31.10 в 20:45 все 11 картов потеряли связь на 12–26 с [измерено], причина не установлена |
| 02.11 21:33 | **порты поменяли** (решение владельца: карты важнее): карты — на встроенный порт, DC — на USB-переходник. Скрипт `C:\FireDrift-тест\net\swap-ports.bat` (от администратора), откат — `net\swap-ports-rollback.bat`, журнал — `net\swap-ports.log` |

### 3.3. Как проверить сеть кассы

Команды PowerShell, по одной. MAC-адреса в чат не копировать.

```powershell
Get-NetAdapter | Select-Object Name, InterfaceDescription, Status, LinkSpeed
```

Должно быть: «Ethernet» — `Up`, «Ethernet 2» — `Up`, адаптер Wi-Fi — `Disabled`.

```powershell
Get-NetIPAddress -AddressFamily IPv4 | Select-Object InterfaceAlias, IPAddress, PrefixLength, PrefixOrigin
```

Должно быть: «Ethernet» — `192.168.1.50`, 24, `Manual`; «Ethernet 2» —
`192.168.88.64`, 24, `Manual`.

```powershell
Get-NetRoute -DestinationPrefix 0.0.0.0/0 | Select-Object InterfaceAlias, NextHop
```

Маршрут по умолчанию — только через «Ethernet 2». Через «Ethernet» его быть не
должно.

```powershell
Test-Connection 192.168.1.1 -Count 2
```

Роутер картов отвечает.

```powershell
Get-NetTCPConnection -LocalPort 8080 -State Listen
```

Маршал слушает порт 8080.

```powershell
(Get-NetTCPConnection -LocalPort 8080 -State Established | Where-Object RemoteAddress -like '192.168.1.*').Count
```

Примерно число картов на связи (плюс планшеты с открытой панелью).

```powershell
curl.exe -s --noproxy "*" http://192.168.1.50:8080/health
```

`{"ok": true, "karts": N}` — маршал отвечает именно по адресу картов.

### 3.4. Если адрес кассы слетел

Признак: **пропали все карты разом**, в логе маршала нет новых `карт
подключился`. Первым делом — `Get-NetIPAddress` (раздел 3.3).

Вернуть адрес — только с владельцем (это сетевые настройки кассы), лучше между
группами:

```powershell
New-NetIPAddress -InterfaceAlias "Ethernet" -IPAddress 192.168.1.50 -PrefixLength 24
```

Без `-DefaultGateway`. Если адрес на адаптере уже есть, но другой, — сначала
снять неверный (`Remove-NetIPAddress`), лучше откатным скриптом
`net\swap-ports-rollback.bat` или повторным `net\swap-ports.bat` от
администратора. Что внутри скриптов — **[не проверено]**, прочитать перед
запуском.

После: через 10–20 с в логе маршала пойдут `карт подключился` и `опознан`
(`ai/10-zhurnaly.md`).

### 3.5. Риски, которые ещё не закрыты

- **`.64` стоит вручную внутри общего пула DHCP MikroTik.** MikroTik может выдать
  этот адрес другому устройству — тогда автоматы потеряют связь с кассой. Нужно
  закрепить `.64` в MikroTik за MAC USB-переходника (MAC — `set.md`). Сделано ли —
  **[не проверено]**; MikroTik не наш, нужен администратор ТЦ.
- **Перезагрузки кассы днём.** 23–24.11 все 6 массовых обрывов — перезагрузки
  кассы через «Пуск» (20–90 с без связи у всех картов) [измерено]. Кто и зачем
  перезагружает — **[не проверено]**. Правило: не перезагружать без нужды и
  только между группами.
- Видно ли панель из сети DC: 01.11 маршал отвечал на `http://192.168.88.64:8080`
  [измерено, до перестановки портов]. Сейчас — **[не проверено]**. Входящий 8080 из
  DC по плану можно было закрыть правилом брандмауэра; сделано ли —
  **[не проверено]**.

## 5. Как найти плату в сети

**DUUID** — номер чипа ESP8266 в десятичном виде; он же последние 3 байта MAC.
Пример на выдуманном числе: DUUID `12345678` = шестнадцатеричное `BC614E` → MAC
кончается на `bc:61:4e`, в Keenetic имя `ESP-BC614E`. Номер карта ↔ DUUID —
`ai/09-karty.md` или `karts.conf`.

Перевод в PowerShell:

```powershell
'{0:x6}' -f 12345678
```

→ `bc614e` (6 знаков, с ведущими нулями).

```powershell
[Convert]::ToInt32('BC614E', 16)
```

→ `12345678` (из имени `ESP-…` обратно в DUUID).

### Способы, от простого к сложному

| Способ | Как | Что получишь |
|---|---|---|
| журнал маршала | строка `карт подключился (192.168.1.x:порт)`, следом `опознан, имя: N` | IP и DUUID в момент подключения (`ai/10-zhurnaly.md`) |
| админка | «Прямой HTTP к плате» → список «Карт N — IP» | IP из телеметрии, для картов на связи |
| админка | «🔍 Найти карты в сети» | все платы, отвечающие на порту 80 (SSDP и опрос подсетей) |
| Keenetic | список устройств: имя `ESP-XXXXXX`, адрес, сигнал | плата в Wi-Fi или нет |
| ARP с кассы | раздел ниже | IP по последним байтам MAC |
| сама плата | `curl.exe --noproxy "*" http://<IP>/config.live.json` | в ответе поле `DUUID` — подтверждение, что это та плата |
| USB | `Какой карт.bat` (`ai/06-instrumenty.md`, раздел 2) | DUUID платы на столе |

### ARP: поиск по MAC

ARP-таблица Windows помнит только тех, с кем касса недавно говорила. Поэтому
сначала «прозвонить» всю подсеть (несколько секунд), потом смотреть таблицу:

```powershell
$p = 1..254 | ForEach-Object { (New-Object System.Net.NetworkInformation.Ping).SendPingAsync("192.168.1.$_", 300) }
```

```powershell
[Threading.Tasks.Task]::WaitAll($p)
```

```powershell
arp -a | Select-String 'bc-61-4e'
```

Вместо `bc-61-4e` — последние три байта своего DUUID через дефис (в `arp -a`
Windows пишет MAC через дефисы, строчными). Нашлась строка — в ней IP платы.

| Что видно | Что значит |
|---|---|
| строка есть | плата в Wi-Fi, IP найден |
| строки нет | плата не в Wi-Fi: питание, антенна, неверные имя или пароль Wi-Fi в плате |
| **два разных IP на один MAC** | плата перезагружается по кругу (чаще всего обрыв дорожки I2C к U3, `docs/montazh.md`) |
| IP есть, `config.live.json` отвечает, а в логе маршала карта нет | плата жива, но не звонит на кассу: в ней не тот адрес сервера (перешить, `ai/06-instrumenty.md`) или у кассы не `.50` |

То же можно делать с ноутбука, подключённого к Wi-Fi картов (пароль —
`set.md`). Ноутбук получит адрес из пула; адрес `.50` ему ставить нельзя.

### 6.3. Как отличить причину конкретного обрыва

Строка обрыва в логе маршала:
`карт отключился — <причина> | на связи N с, последний кадр N с назад`.

| Признак | Что это |
|---|---|
| в ту же секунду отвалились 3+ карта | общая причина: касса, роутер, эфир. Проверить аптайм Keenetic, журнал Windows кассы, сеть кассы (раздел 3.3) |
| `Windows оборвала соединение сама (WinError 10053)` у нескольких сразу | у кассы пропадала сеть |
| `плата закрыла соединение`, `плата закрыла вебсокет (close N)` | решение прошивки платы |
| `соединение сброшено со стороны платы (WinError 10054)` | обычно плата переподключала Wi-Fi |
| `плата перестала подтверждать данные (таймаут TCP)` | плата замолчала: зависла, пропало питание или радио |
| `мусор …`, `битые байты …`, `кадр длиной …` | плата прислала обрезанный кадр |
| после возвращения `uptime` начался с нуля, `reboots` вырос | плата перезагрузилась (утреннее включение — тоже «перезагрузка») |
| перед обрывом `rssi` хуже −75 | слабый сигнал: антенна, металл рядом |
| в журнале Keenetic тишина / deauth+associated / выкинут через ~630 с | раздел 2.4 |

Норма для ориентира: один обрыв в час на карт бывает у любого (сентябрь–октябрь);
21–25.11 — около одного сбоя платы на 30 карт-часов [измерено]. Чинить карт,
который заметно выбивается из остальных. Поиск по журналам — `ai/10-zhurnaly.md`,
разбор по шагам — `ai/08-diagnostika.md`.
