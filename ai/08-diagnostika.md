# 08. Диагностика: симптом → шаги

Файл для ИИ-агента. Деревья неисправностей: по каждому симптому — шаги в порядке
проверки. Сначала то, что не требует рук и инструментов (телеметрия, журнал, глаза),
потом мультиметр, последним — замена деталей (её делает опытный).

Метки достоверности:

- **[измерено, дата]** — телеметрия, журнал, мультиметр;
- **[владелец]** — со слов владельца или по его фото;
- **[разбор прошивки]** — прочитано в коде прошивки (25.11.2026);
- **[не проверено]** — гипотеза, расчёт, типовое для такого железа. В скобках —
  откуда.

Связанные файлы: безопасность — `ai/01-bezopasnost.md`, устройство —
`ai/02-zhelezo.md`, прошивка — `ai/03-proshivka.md`, сервер — `ai/04-marshal.md`, сеть
— `ai/05-set.md`, инструменты (тест-драйв, USB-лог, `config.live.json`) —
`ai/06-instrumenty.md`, замеры И1–И18 — `ai/07-izmereniya.md`, карты —
`ai/09-karty.md`, журналы — `ai/10-zhurnaly.md`, открытые вопросы —
`ai/11-otkrytye-voprosy.md`.

## 0. Как вести разбор

1. **Спросить** (по одному вопросу):
   - номер карта на кузове;
   - что именно человек видел и слышал: свет, дисплей, звук, движение, педаль;
   - когда — по часам; если по таймеру панели, перевести (раздел 1.3);
   - всегда или иногда, повторяется ли на подставке;
   - что делали с картом перед этим: меняли, мыли, заряжали, роняли;
   - есть ли сейчас гость в карте, идёт ли заезд.
2. **Безопасность.** Есть признак из стоп-крана (`ai/01-bezopasnost.md`, раздел 9) —
   сначала он, ветки потом.
3. **Номер → DUUID** (`ai/09-karty.md`), **время → файл журнала** (`ai/10-zhurnaly.md`).
   Посмотреть историю карта в `ai/09-karty.md`: что ломалось, то и ломается.
4. **Выбрать ветку** (раздел 2) и идти по шагам.
5. **Формат шага:** что сделать → зачем → что должен увидеть → куда дальше, если так и
   если иначе. Перед шагом руками — чек-лист `ai/01-bezopasnost.md`, раздел 3.
6. **Вывод — только после подтверждения** телеметрией, журналом или глазами человека.
   Гипотезу называть гипотезой.
7. **Записать** результат (раздел 4).

## 1. Без инструментов: телеметрия и журнал

### 1.1. Где смотреть

| Что | Где | Как часто | Подробно |
|---|---|---|---|
| Живые поля карта | админка `http://192.168.1.50:8080/admin` → «Живые поля» → выбрать карт (с сети DC — `http://192.168.88.64:8080/admin`); пароль — в FireDrift_Access | раз в 3 с | `ai/04-marshal.md`, `ai/06-instrumenty.md` |
| Поля прямо с платы | `config.live.json` по адресу платы | по запросу | `ai/06-instrumenty.md` |
| Журнал маршала | на кассе `C:\FireDrift-тест\marshal\logs\marshal-ГГГГ-ММ-ДД_ЧЧ.log`, строки `Status` | раз в 6 с на карт | `ai/10-zhurnaly.md` |
| Журнал роутера | на кассе `keenetic-logs\` | события Wi-Fi | `ai/05-set.md`, `ai/10-zhurnaly.md` |
| Лог платы по USB | ноутбук на стенде | всё, что печатает плата | `ai/06-instrumenty.md` |

События короче 6 с в журнале можно не увидеть. Что значит каждое поле —
`ai/02-zhelezo.md`, раздел 4.

### 1.2. Строки журнала, которые нужны чаще всего

| Строка (начало) | Что значит |
|---|---|
| `заезд N мин, скорость «…» (L)` / `ТЕСТ-ДРАЙВ N мин …` | старт; L — настоящий лимит |
| `разрешаю движение → … — ок` | реле включено командой `/On6` |
| `… — НЕ ПРОШЛО: …` | команда до платы не дошла |
| `продление без Stop: кусок N с, лимит L` | бесшовное продление, гость ничего не заметил |
| `продление заезда: кусок N с, всего осталось M с` | продление через `Stop`: свет и реле гаснут на ~2 с |
| `продление без Stop не подтвердилось за 20 с — продлеваю через Stop` | бесшовное не вышло, пошло через `Stop` |
| `щелчок I/O посреди заезда, педаль отпущена (adcIn=N) — перевзвожу плату…` | гость включил I/O после старта; свет мигнёт ~2 с один раз |
| `… педаль нажата (adcIn=N) — перевзведу, как только отпустят` | маршал ждёт отпускания педали |
| `перевзвод после щелчка I/O: кусок …` | перевзвод сделан |
| `докатка: выход 7 снят, лимит N` | последняя минута: свет гаснет, лимит 20 — норма |
| `заезд закончен` | конец |
| `карт отключился — <причина> \| на связи N с, последний кадр N с назад` | обрыв связи (раздел Д6) |
| `карт подключился (…)` | вернулся |
| `ЗАЩИТА: …` | сервер увидел беду на плате: 255 или местное катание (Д3, `ai/04-marshal.md`) |
| `ВНИМАНИЕ: driveOn=1 вне заезда …` | сторож свободного карта (`ai/04-marshal.md`) |

### 1.3. Таймер панели → часы

Таймер панели показывает **оставшееся оплаченное время**. Часы события = время конца
оплаты − показание таймера. Время конца оплаты = старт + длина заезда (строка
`заезд N мин` в журнале).

Пример (№13, 25.11): старт 18:54:49, заезд 30 мин → оплачено до 19:24:49. «На таймере
21:00» = 19:24:49 − 21:00 = **19:03:49** (`ai/istochniki/karty-kontekst-ii-2026-11-25.md`,
раздел 6).

### 1.4. Как включить реле для проверки

Только **официальный тест-драйв админа** из панели (1, 3 или 5 минут), карт на
подставке (`ai/01-bezopasnost.md`, раздел 2). В конце тест-драйва — минута докатки
(лимит 20, свет погашен), затем реле выключается.

## 2. Указатель: симптом → ветка

| Симптом словами человека | Ветка |
|---|---|
| нажимаю педаль — не едет | Д1 |
| педаль «не видно», `adcIn` не меняется | Д2 |
| в панели красная плашка «Защита: сбой платы», в полях 255 | Д3 |
| встал посреди заезда, поехал, когда отпустили педаль | Д4 |
| подсветка мигнула, погасла, не гаснет, не горит | Д5 |
| «нет связи», карт пропадает из панели | Д6 |
| `uptime` сбросился, карт перезагружается | Д7 |
| карт вообще не появляется, не заходит в Wi-Fi | Д8 |
| всё мёртвое: дисплей, свет, карт не в панели | Д9 |
| едет слишком быстро или медленно, режим не тот | Д10 |
| колесо дёрнулось один раз и стоит | Д11 |
| бьётся током, щиплет | Д12 |
| едет, хотя заезда нет (`kOn=0`) | Д13 |

## 3. Ветки

### Д1. Карт не едет

Ссылки: `docs/montazh.md` «Карт в панели, но не едет», `ai/02-zhelezo.md` разделы
3.6–3.7, замеры И5–И9.

**Д1.1. Включено ли реле.**
- Сделать: в «Живых полях» выбрать карт, посмотреть `kOn`. Карт свободен — запустить
  официальный тест-драйв, карт на подставке.
- Зачем: без реле контроллер выключен, карт не поедет никогда.
- Ожидаем: `kOn=1` в заезде или тест-драйве.
- `kOn=1` → Д1.3. `kOn=0` → Д1.2. Карта нет в живых полях → Д6 или Д8.

**Д1.2. Почему реле выключено.**
- Сделать: в журнале за эту минуту найти строки карта (раздел 1.2).
- Что бывает:
  - `НЕ ПРОШЛО` — команда не дошла до платы → Д6;
  - `ЗАЩИТА: сбой платы …=255` и отказ старта «карт неисправен — …» → Д3;
  - `ЗАЩИТА: … местном режиме` → `ai/04-marshal.md`, «Защита»;
  - перед этим `продление заезда` и после него `kOn` так и остался 0 — так ложились 2
    продления из 252 до 02.11, сервер исправлен **[измерено]**. Повторилось — сохранить
    журнал, сказать владельцу (`ai/04-marshal.md`);
  - `uptime` сбросился — плата перезагрузилась → Д7;
  - строк нет, а с последнего `Start` прошло больше 600 с — плата сама сняла реле по
    таймауту ожидания **[разбор прошивки]** → `ai/04-marshal.md`, «Продление».

**Д1.3. Включён ли переключатель I/O.**
- Сделать: посмотреть `dIn`.
- Зачем: при выключенном I/O прошивка держит газ на холостом (45) — карт не поедет даже
  при `kOn=1` **[разбор прошивки]**.
- `dIn=1` → Д1.4.
- `dIn=0` → попросить включить I/O на корпусе. `dIn` стал 1 и карт поехал — причина
  найдена; гостю: включать I/O до старта. Включили, а `dIn` остался 0 — линия I/O: замер
  И8.

**Д1.4. Горит ли дисплей.**
- Сделать: спросить, горит ли дисплей на руле при `kOn=1`.
- Зачем: на большинстве картов контроллер питается через реле; дисплей горит —
  контроллер включён.
- Горит → Д1.5. Тёмный → Д9, шаг Д9.3.

**Д1.5. Читается ли педаль.**
- Сделать: нажать педаль до упора и отпустить, смотреть `adcIn`.
- Ожидаем: 43–45 отпущена, 182–188 в пол (своя норма карта — `ai/09-karty.md`).
- Растёт → Д1.6. Не меняется, скачет, странные числа → Д2. 255 → Д3.

**Д1.6. Выдаёт ли плата газ.**
- Сделать: педаль в пол, смотреть `adc0` и `Speed`.
- Ожидаем: `adc0` по формуле: при лимите 20% ≈104, 50% ≈134, 75% ≈159, 100% ≈184
  (`ai/02-zhelezo.md`, раздел 3.6).
- По формуле → Д1.7.
- `adc0` стоит на 43–45, а педаль в пол: прошивка держит холостой. Ещё раз проверить
  `kOn` и `dIn`. Всё в норме, а газа нет — сохранить строки журнала, сказать владельцу.
- `adc0` низкий, потому что `Speed` маленький (например, 20 — докатка) — норма для
  этой фазы.

**Д1.7. Крутится ли колесо на подставке.**
- Сделать: педаль в пол на подставке. Смотреть на колесо и на `aIn`.
- Крутится → на подставке всё работает. На трассе «не едет» — нагрузка: батарея под
  током (И2), отсечка 30 В, тормоз. Дальше Д1.9.
- Дёрнулось один раз и стоит → Д11.
- Не крутится совсем → Д1.8.

**Д1.8. Не блокировка ли и доходит ли газ до контроллера.**
- Сделать: полностью отпустить педаль, подождать 2 с, плавно нажать снова.
  - Поехал → это была блокировка контроллера (Д4).
- Сделать: замер И7 — `J10` при педали в пол.
  - На `J10` около 0, хотя `adc0` растёт → нет `R11` или дорожки до `J10`; плату
    смотрит опытный.
  - На `J10` по расчёту, а у разъёма контроллера (сзади разъёма) нет → провод или
    разъём `J10` → контроллер (И15).
  - До входа контроллера газ доходит → тормоз (отсоединить `T1`, Д11.4), включение
    контроллера (И9), мотор и контроллер (Д11).

**Д1.9. Батарея.**
- Сделать: `aIn` в покое и под газом в журнале (И2), батарея мультиметром (И1).
- Ниже 35 В в покое или проседает к 30–31 В под газом → зарядить, проверить блоки.

Ещё: если педаль идёт прямо в контроллер мимо платы, а провода газа сидят на одном
`J9` (так было на всех картах до 09.09), лимит не работает, но карт едет
(`docs/montazh.md`).

### Д2. Педаль не читается (`adcIn` стоит)

Ссылки: `docs/montazh.md` «Педаль не отзывается», `ai/02-zhelezo.md` 2.5 и 3.6, замеры
И5, И6, И13, И15.

**Д2.1. Реле включено?**
- При `kOn=0` педаль на большинстве картов без питания: `adcIn` 0–2 — **норма**
  **[измерено: журналы]**. У №15 педаль живая и при `kOn=0`.
- Сделать: запустить тест-драйв, карт на подставке. Дальше Д2.2.

**Д2.2. На каком числе стоит `adcIn`.** Нажимать медленно до упора и отпускать.

| Что видно | Значит | Дальше |
|---|---|---|
| ровно 0, `adc0` 43–45 | нет питания педали или обрыв сигнала | Д2.3 |
| 0 **одновременно** в `adcIn`, `adc0` и `adc3` | PCF8591 читает ноль на всех каналах — питание, земля или опора U3 под нагрузкой | Д2.6 |
| 43–45 и не растёт | педаль запитана, но сигнал не меняется: датчик педали или сигнальный провод | Д2.4 |
| скачет, временами ниже 30 | плохой контакт: разъём педали, `J9`, пайка `R1` | Д2.5 |
| в покое около 98–100, в пол 211–216 | уровень сдвинут, как у №10 | Д2.7 |
| 255 | сбой шины I2C | Д3 |

**Д2.3. `adcIn=0`: есть ли питание педали.**
- Сделать: горит ли дисплей? Тёмный → контроллер не включён → Д9.3.
- Сделать: замер И5 (питание педали).
  - 0 при горящем дисплее → обрыв красного или чёрного провода педали, разъём (И15).
  - Около 5 В → замер И6 (сигнал у педали): растёт при нажатии → обрыв между педалью и
    `J9` (синий провод, разъём, `R1`); не растёт → педаль.

**Д2.4. `adcIn` стоит на 43–45.**
- Сделать: замер И6, шаг 1 (сигнал у самой педали).
  - Не растёт → неисправна педаль. Замену делает опытный или человек по его указанию,
    с отключённой батареей.
  - Растёт → И6, шаг 2: растёт ли `J9` относительно земли платы. Растёт `J9`, а `adcIn`
    нет → `R1`, PCF8591 — плату смотрит опытный. Не растёт `J9` → провод или разъём.

**Д2.5. `adcIn` скачет.**
- Сделать: прозвонка с шевелением (И15) разъёма педали, синего провода до `J9`. Под
  питанием — простукивание (Д3.5), глядя на `adcIn`.

**Д2.6. Все три канала в 0 при включённом реле.**
- Что это: PCF8591 отвечает, но меряет ноль. Видели у №4 09.09 (каждый раз при
  включении реле, плата ещё и перезагружалась в заездах), №15 08.09 (≈15 минут), №7
  09.09 **[измерено: журналы]**. При выключенном реле у №4 всё было нормально.
- Гипотеза: при включении контроллера просаживается 5 В, земля или опора VREF платы
  **[не проверено]**.
- Сделать по порядку: И4 шаг 4 (5 В в момент щелчка реле), И3 шаги 3–4 (минус платы
  под нагрузкой), И11 с опытным (VDD и VREF U3), прозвонка земли платы (И12, строка 2).
- Педаль при этом не виновата: с нулём на входе прошивка выдаёт ноль газа, контроллер
  стоит.

**Д2.7. Сдвинутый уровень, как у №10.**
- Сделать: И6 шаг 2 (сравнить сигнал у педали и на `J9` относительно земли платы), И7
  (`J10` в покое: выше 1,1 В — опасно), И13 (сопротивления `J9`/`J10` против исправной
  платы).
- К гостям не выпускать, пока в покое на `J10` больше 1,1 В.
- Подробная история №10 — `ai/09-karty.md`.

### Д3. Педаль или газ 255

Ссылки: `docs/server.md` «Защита по телеметрии», `ai/03-proshivka.md` раздел 4,
`ai/04-marshal.md`, история №12 — `ai/09-karty.md`.

**Д3.0. Сразу.**
- **Карт к гостям не выпускать.** Сервер сам закрывает заезд, показывает красную плашку
  «Защита: сбой платы: …=255» и 10 минут отклоняет старт («карт неисправен — …»).
  Снять раньше можно только перезапуском маршала — это решает владелец, не во время
  смены.
- Почему опасно: ошибка чтения шины I2C даёт «педаль 255». Плата считает это «в пол» и
  выдаёт газ выше лимита: 170 при 50%, 255 при 100% **[разбор прошивки]**. Если шина
  отказала целиком, ЦАП может держать последний газ до выключения реле **[разбор
  прошивки: вывод, не проверено]**.

**Д3.1. Прочитать журнал вокруг события.**
- Сделать: строки `ЗАЩИТА` и `Status` карта за 2 минуты до и после (`ai/10-zhurnaly.md`).
- Смотреть: в каких полях 255 (`adcIn`, `adc0`, `adc3`), `kOn`, `Speed`, `aIn`,
  `uptime`.
  - 255 во всех трёх — отказ шины I2C (D1 mini ↔ PCF8591).
  - Одновременно `aIn=0_0.00` — пропал и вход I/O (так было у №12 09.09 в 20:32
    **[измерено]**): похоже на контакт или землю платы **[не проверено]**.
  - После 255 `uptime` сбросился — плата перезагрузилась (№12 22.11) → смотреть и Д7.

**Д3.2. Камеры.**
- Ехал ли карт в эти секунды быстрее обычного — по камерам. Для №12: 22.11
  17:19:50–17:20:40 (`ai/istochniki/karty-itog-2026-11-25.md`, §7). Смотрит владелец.

**Д3.3. Повторить на подставке.**
- Сделать: карт на подставке, официальный тест-драйв, педаль зажата в пол (грузом или
  ремнём), 20–25 минут. Смотреть `adcIn` в «Живых полях», в журнале — строки `ЗАЩИТА`.
- Пример: №12 25.11, 16:02–16:27, лимит 75% — ни одного 255, `adcIn` 183–185, `adc0`
  156–159, `aIn` 40,8 В без проседания, ни одной перезагрузки и обрыва **[измерено
  25.11]**.
- Повторилось → Д3.5, чтобы найти место. Не повторилось → Д3.4.

**Д3.4. Не повторяется на подставке.**
- Вывод **[не проверено]**: сбой зависит от вибрации или тока на трассе — вероятнее
  всего, контакт: пайка D1 mini или PCF8591, разъём, жгут.
- Дальше — простукивание (Д3.5).

**Д3.5. Простукивание.**
- Сделать: та же постановка, что в Д3.3 (`adcIn` стоит ровно около 184).
- **Пластиковой палочкой** (не металлом) постукивать по одному месту 10 секунд, потом
  10 секунд пауза. Агент называет место, человек называет время по часам.
- Порядок мест: D1 mini (корпус модуля); PCF8591 (U3); 3-пин разъём педали; 3-пин
  разъём контроллера; чёрный JST (`J3`, `J4`); белые 2-пин; жёлто-зелёный провод `J1`
  у платы; жгут от платы к педали по всей длине; крепление платы.
- Что ищем: `adcIn` прыгает в 255 или в 0, `adc0`/`adc3` прыгают, `uptime` сброшен,
  карт отключился.
- После — проверить журнал по записанным минутам (опрос раз в 6 с: в живых полях раз в
  3 с можно пропустить).
- Нашли место → Д3.6. Не нашли → Д3.7.

**Д3.6. Место найдено.**
- Отключить батарею, показать место опытному (перепайка, замена разъёма). Записать в
  `ai/09-karty.md`. После ремонта повторить Д3.3.

**Д3.7. Не нашли — с опытным.**
- Прозвонка шины I2C с шевелением (И14), VDD и VREF U3 (И11), минус платы под нагрузкой
  (И3 шаги 3–4), 5 В при щелчке реле (И4).
- USB-лог на стенде во время теста (`ai/06-instrumenty.md`) — увидеть перезагрузки.
- Пробная замена платы (опытный).

### Д4. Встал посреди заезда, поехал после отпускания педали

Ссылки: `ai/04-marshal.md` «Продление», `ai/02-zhelezo.md` 2.3 (блокировка),
`ai/istochniki/karty-kontekst-ii-2026-11-25.md` разделы 5–6 (разбор №13).

**Д4.1. Расспросить.** Гас ли свет на пару секунд? Гас ли дисплей? Поехал, когда гость
отпустил педаль? Перевести время в часы (раздел 1.3).

**Д4.2. Журнал за эту минуту.**
- Найти: `продление заезда: кусок …` (через `Stop`), `продление без Stop не
  подтвердилось …`, `перевзвод после щелчка I/O …`.
- Признак в `Status`: `kOn` 1 → 0 на 1–6 с → 1, `adcIn` высокий, `aIn` не проседает.
- Нашли → **это блокировка контроллера.** Реле упало, контроллер включился с нажатой
  педалью и ждал, пока её отпустят **[владелец: №13 25.11]**. Карт исправен.
  - Почему пошло через `Stop`: гость включил I/O после старта (плата перешла в
    «катание», `timeDriveOn=1`), телеметрия была старой или бесшовное продление не
    подтвердилось за 20 с (`ai/04-marshal.md`).
  - Что сказать гостю: полностью отпустить педаль и нажать снова.
  - Профилактика: включать I/O до старта заезда.
- Не нашли → Д4.3.

**Д4.3. Перезагрузка?**
- `uptime` сбросился в эту минуту → плата перезагрузилась, реле упало, дальше та же
  блокировка → Д7.

**Д4.4. Реле не падало (`kOn` всё время 1).**
- `dIn` мигал 1 → 0 → 1 или `timeDriveOn` сменился с 0 на 1 без участия гостя — плохой
  контакт переключателя I/O: на каждом «выключено» прошивка ставит холостой газ
  **[не проверено: вывод из разбора прошивки]**. Замер И8 (три включения), прозвонка с
  шевелением разъёмов I/O (И15).
- `aIn` упал к 30–31 В — отсечка контроллера по разряду → батарея (И1, И2).
- Ничего из этого → контроллер, тормоз → Д11.

**Д4.5. После продления карт так и стоял до конца (`kOn=0`).** Сохранить журнал,
сказать владельцу (`ai/04-marshal.md`).

### Д5. Свет мигнул или погас

Ссылки: `ai/02-zhelezo.md` 2.9 и 3.8, `docs/server.md` «Фазы заезда», замер И10.

**Д5.1. Когда.** Перевести время в часы, найти строки журнала.

| Что в журнале | Значит |
|---|---|
| `докатка: выход 7 снят, лимит N` | последняя минута заезда: свет гаснет на 60 с — **норма** |
| `перевзвод после щелчка I/O` в начале заезда | гость включил I/O после старта: свет мигнул ~2 с один раз — **норма** |
| `продление заезда: кусок …` | продление через `Stop`: свет и реле гаснут на ~2 с. Если карт после этого стоял — Д4 |
| `uptime` сброшен | перезагрузка платы → Д7 |
| ничего из этого | Д5.2 |

**Д5.2. Что говорит `kOn1`.**
- `kOn1=1`, а свет не горит — неисправность после платы: красный провод чёрного JST
  (`J4`), DC-DC 12 В, Bluetooth-контроллер ленты, лента. Замер И10, осмотр разъёмов.
- `kOn1=0`, а должно быть 1 (не докатка) — сервер не поднял выход 7 или плата не
  приняла: журнал, `ai/04-marshal.md`.
- Нерешённый случай: №13 25.11 — телеметрия говорит «свет включён» в 19:03:48, владелец
  видел его погасшим примерно до 19:04:19 **[не выяснено]**.

**Д5.3. Свет не гаснет на докатке.** Лента запитана мимо платы — известно для №1, №10,
№11, №14 (`docs/montazh.md`). Чинит опытный (`R7`, `VT2`).

**Д5.4. Свет не горит никогда.**
- `kOn1=1`? Замер И10: на `J4` есть напряжение → DC-DC, контроллер ленты, лента. Нет →
  `F1`, `VT1`, `VT2` на плате **[не проверено: по схеме]** — плату смотрит опытный.

### Д6. Карт «нет связи» или отваливается

Ссылки: `ai/05-set.md`, `docs/server.md` «Логи», `ai/istochniki/karty-itog-2026-11-25.md`
§3.

**Д6.1. Один карт или все сразу.**
- Отвалились многие в одну минуту — общая причина: перезагрузка кассы (6 раз за
  23–24.11), перезапуск маршала, перезагрузка роутера (27.10 14:14 все 10 картов за 7
  мс). Это не ремонт карта → `ai/05-set.md`, `ai/04-marshal.md`.
- Один карт → Д6.2.

**Д6.2. Причина в строке обрыва.** `карт отключился — <причина> | на связи N с,
последний кадр N с назад`:

| Причина | Значит |
|---|---|
| `плата закрыла соединение`, `плата закрыла вебсокет (close N)` | плата сама закрыла связь — решение её прошивки |
| `соединение сброшено со стороны платы (WinError 10054)` | обычно плата переподключила Wi-Fi |
| `Windows оборвала соединение сама (WinError 10053)` | плата перестала подтверждать данные или у кассы пропала сеть |
| `мусор …`, `битые байты …`, `кадр длиной …` | плата прислала обрезанный кадр, сервер оборвал связь; на сервере ещё не исправлено |

Другие формулировки бывают (например, «плата перестала подтверждать данные (таймаут
TCP)» у №15 25.11) — смысл тот же, что у 10053.

**Д6.3. Перезагрузилась ли плата.**
- После `карт подключился` `uptime` начался с нуля → перезагрузка → Д7.
- Не сбросился → плата рвёт связь сама, без перезагрузки. Так было в 9 из 13 сбоев
  21–25.11: карт стоял, сигнал хороший, роутер связь не терял **[измерено]**. Гость этого
  не замечает: карт едет дальше. Причина — в прошивке, ремонтом карта не лечится.

**Д6.4. Сигнал.** `rssi` перед обрывом хуже −75 → антенна. Посмотреть край D1 mini с
зигзагом: не прижат ли к металлу, нет ли на нём термоклея (так было у №10 и №14,
`docs/montazh.md` §8). Отодвигает и чистит опытный.

**Д6.5. Журнал роутера** (`ai/05-set.md`):
- через ~630 с роутер выкидывает плату «за молчанием» — у платы пропало радио: карт
  выключили или пропало питание;
- сразу «deauth + associated» — плата перезагрузилась;
- в журнале роутера тишина — Wi-Fi держался, рвалась только связь с сервером.

**Д6.6. Как часто.** Один обрыв в час бывает у любого карта. Разбираться, если больше
двух в час сверх общих. Тогда: замок и разъём питания платы (совет отчёта кассы для №2
и №15), И3 и И4 при щелчке реле, USB-лог на стенде (`ai/06-instrumenty.md`).

**Д6.7. Не возвращается долго.** Подойти к карту: горит ли подсветка (у платы без
сервера свободный карт сам зажигает выход 7 в местном режиме **[разбор прошивки]**),
включён ли главный выключатель. Похоже на «всё мёртвое» → Д9. Плата жива, но не в сети →
Д8. Без гостя и без заезда можно выключить и включить карт главным выключателем и
записать, вернулся ли он.

### Д7. Плата перезагружается

Ссылки: `docs/montazh.md` «Карт перезагружается сам», `ai/03-proshivka.md` разделы 7 и
9, `ai/06-instrumenty.md` (USB-лог, второй переходник), замеры И3, И4, И14.

**Д7.1. Подтвердить.** В `Status` `uptime` начался заново, `reboots` вырос, перед этим
обрыв и `карт подключился`. Записать времена.

**Д7.2. Когда случается.**
- В заезде (реле включено) — при включённом реле плата перезагружается в 7–11 раз
  чаще, чем на стоянке **[измерено: перепись 25.10–02.11]**. Подозрение — питание под
  нагрузкой **[не проверено]**.
- Сразу после включения карта, перед сбросом включался выход 7 (№2 23.11, №13 29.10) —
  подозрение на питание при включении: замок, разъём **[не проверено]**.
- Сама плата перезагружается только после 12 часов без связи **[разбор прошивки]** —
  дневные перезагрузки этим не объясняются.

**Д7.3. Цикл без конца.** Плата не держится в сети ни минуты, у кассы `arp -a`
показывает два разных IP на один MAC — чаще всего оборвана дорожка I2C к PCF8591
(`docs/montazh.md`) → И14.

**Д7.4. USB-лог на стенде** (`ai/06-instrumenty.md`). Карт на подставке, ноутбук от
батареи, кабель с изолентой на +5 В. Воспроизвести: тест-драйв, педаль, включения
реле.
- `Exception`, `Soft WDT`, `>>>stack>>>` — упала программа (не питание).
- Мусор с пометкой `ПЕРЕЗАГРУЗКА` — загрузчик на 74880, плата перезапустилась.
  Сверить с `uptime` в телеметрии: настоящая перезагрузка его сбрасывает.
- Порт пропал (на кабеле с изолентой) — у платы пропало питание.
- Причина сброса — только вторым переходником на 74880: 1 — включение или провал
  питания; 2 — ножка RST (помеха) или программный перезапуск; 4 — аппаратный сторожевой
  таймер (`ai/03-proshivka.md`, раздел 9).

**Д7.5. Питание мультиметром.** И4 (5 В, особенно в момент щелчка реле), И3 (`J1` и
минус платы под нагрузкой). Осмотр замка и разъёма питания.

**Д7.6. Механика.** Простукивание (Д3.5), глядя на `uptime` и на порт USB.

**Д7.7. Ремонт** — опытный: контакты питания; конденсатор у D1 mini при причинах 1 и 2
(`docs/montazh.md`); замена платы.

### Д9. «Весь карт мёртвый»

Ссылки: `ai/02-zhelezo.md` 3.4, замеры И1, И3, И4, И9, история запасной платы —
`ai/09-karty.md` (№10, 02.11).

**Сначала:** у свободного карта **дисплей тёмный — это норма**: контроллер включается
только реле, во время заезда или тест-драйва. Подсветка у свободного исправного карта
горит.

**Д9.1. Что именно мёртвое.**
- (а) дисплей тёмный во время официального тест-драйва;
- (б) подсветка тоже не горит;
- (в) карта нет в панели.

**Д9.2. Простое.** Включён ли главный выключатель? Вставлен ли силовой разъём? Заряжена
ли батарея (И1)? Меньше 35 В в покое — зарядить.

**Д9.3. Жива ли плата** (карт в панели, живые поля обновляются).
- Жива, тест-драйв даёт `kOn=1` (слышен щелчок реле), а дисплей тёмный → контроллер не
  получает включение. Замер И9 (`J3`): при `kOn=1` есть напряжение — обрыв от `J3` до
  контроллера или контроллер; нет — реле. Дальше — опытный.
- Жива, но `kOn` остаётся 0 → Д1.2.
- Не жива → Д9.4.

**Д9.4. Питание платы.** Замер И3: `J1` относительно минуса батареи.
- 0 → жёлто-зелёный провод `J1`, его соединение с плюсом.
- Есть → И3 шаг 2 (`J1` относительно земли платы). 0 → у платы нет минуса (главный
  выключатель, провод минуса; откуда плата берёт минус, не выяснено) → опытный.

**Д9.5. 5 В на плате** (И4).
- 0 при живом `J1` → коснуться `F2` и понижайки (`ai/01-bezopasnost.md`, 5.3). **Горячо
  — стоп-кран, плату не включать.** Холодно → `F2`, понижайка, `ZD2`, `D1` — плату
  меняет опытный.
- 5 В есть, а платы нет в сети → Д8.

**Д9.6. Запасная плата.** Перед установкой: подключить, через минуту `F2` холодный,
5 В в норме (И4), плата появилась в сети. 02.11 запасная плата на №10: `F2` горячий,
карт «кусался», потом «весь карт мёртвый» — с коротким замыканием в плате нет 5 В,
реле не включается, контроллер выключен **[владелец 02.11]**. Такую плату не включать,
пока опытный не проверит `U2` и `F2`.

### Д10. Скорость не та

Ссылки: `ai/04-marshal.md` «Скорость», `docs/server.md` «Скорость по градациям»,
`ai/02-zhelezo.md` 2.7 и 3.6.

**Д10.1. Расспросить.** Быстрее или медленнее? Один карт или все? С какого времени?
Какой режим (Новичок, Обычный, Профи)? Старт из CRM или из панели?

**Д10.2. Какой лимит поставил сервер.** Строка `заезд N мин, скорость «…» (L)`: L —
настоящий лимит.
- Старт из CRM — L равен ползунку карта (`<DUUID>.speed` в `karts.conf`). Название в
  кавычках при этом только надпись.
- Старт из панели — таблица «Скорость по картам» (`<DUUID>.preset.<градация>`), а если
  пусто — общие значения (`speeds`).
- С 25.11 18:52 у всех картов в таблице: Новичок 50, Обычный 70, Профи 90; общие:
  Обычный 70, Новичок 50, Профи 100 (`ai/istochniki/karty-kontekst-ii-2026-11-25.md`,
  раздел 3).
- Ползунок в панели и `/api/v1/speed` посреди заезда меняют лимит до конца заезда.

**Д10.3. Дошёл ли лимит до платы.** `Speed` в телеметрии = L? Не равен → сервер
(`ai/04-marshal.md`).

**Д10.4. Режет ли плата газ.** Педаль в пол, `adc0` по формуле для этого `Speed`
(`ai/02-zhelezo.md`, 3.6)?
- Да, а скорость карта от лимита не меняется → плата не управляет газом: оба провода
  газа на `J9`, педаль прямо в контроллер, нет `R11`. Замер И7, осмотр проводов
  (`docs/montazh.md`, «Скорость не регулируется»).

**Д10.5. Физика.** Положение переключателя 高中低 — одинаковое на всех картах (8, 18,
24 км/ч). Батарея (`aIn`, И1). Подтормаживает ли колесо **[не проверено]**.

**Д10.6. Проценты лимита нелинейны.** Это не неисправность.
- Первые 85 единиц газа (около 1,67 В) проходят при любом лимите, а контроллер
  трогается примерно с 1,1 В **[разбор прошивки; расчёт]**. Поэтому лимит 0% тоже едет,
  а 60% дают больше 60% скорости.
- Доля полного газа ≈ 0,23 + 0,77 × лимит **[не проверено: расчёт, педаль в пол 184,
  VREF 5 В]**:

  | Лимит | 0% | 20% | 30% | 50% | 60% | 75% | 100% |
  |---|---|---|---|---|---|---|---|
  | Доля газа | 0,23 | 0,38 | 0,46 | 0,61 | 0,69 | 0,81 | 1,00 |

- Пример **[оценка, не проверено]**: если на 100% карт едет 30 км/ч, то 60% дают около
  21 км/ч, а не 18. Это ещё и при допущении, что скорость пропорциональна газу; так ли у
  нашего контроллера, не проверено.
- Колесо в воздухе без нагрузки крутится быстрее, чем на трассе: на подставке скорость
  не калибровать.
- Почему на высоком режиме минимальный лимит даёт около 14 км/ч, не выяснено
  (`docs/voprosy.md`, вопрос 5).

**Д10.7. Калибровка на трассе.** Только с разрешения владельца, вне работы с гостями,
ездит сотрудник.
1. Батарея заряжена (И1), переключатель 高中低 в общем положении, водитель один и тот же.
2. Официальный тест-драйв. Лимит 30% ползунком в панели.
3. На прямой педаль в пол, максимальная скорость с дисплея. Два проезда.
4. То же для 50%, 75%, 100%.
5. Записать: карт, дата, напряжение батареи, положение переключателя, «лимит → км/ч».
   В `ai/09-karty.md`.
6. Лимиты по картам в таблице «Скорость по картам» выставляет владелец.

### Д11. Тик и стоп при нажатии (защита контроллера)

Ссылки: `ai/02-zhelezo.md` 2.3–2.4, замеры И1, И2, И9, И15, И17, И18, история №10 —
`ai/09-karty.md`.

**Д11.1. Расспросить.** Колесо дёрнулось один раз и стоит, пока педаль нажата? Что
дисплей в этот момент: горит ровно, мигает, гаснет?

**Д11.2. Не блокировка ли.** Полностью отпустить педаль, подождать 2 с, плавно нажать.
Поехал → это была блокировка (Д4).

**Д11.3. Дисплей мигает или гаснет при тике** → проваливается питание: батарея (И1,
`aIn` под газом, И2), силовой разъём, главный выключатель, контакт включения контроллера
(И9). Силовую проводку смотрит опытный.

**Д11.4. Дисплей горит ровно** → контроллер сам отключает мотор: защита по фазам или
датчикам, выгоревший ключ, тормоз **[не проверено: вывод по №10]**. По порядку:
1. Меняли недавно колесо или контроллер? Тогда порядок фаз и Холлов мог не совпасть:
   самообучение контроллера **[не проверено: типовое]** — опытный.
2. Тормоз: выключить тест-драйв, отсоединить разъём `T1`, снова тест-драйв и газ.
   Поехал → датчик тормоза или его провод замыкает вход на минус (И17).
3. Батарея отключена: осмотреть толстый трёхфазный разъём мотора и тонкий разъём
   Холлов — сидят до конца, нет потемневших или оплавленных контактов, провода не
   вырваны (И15).
4. Датчики Холла (И18) — с опытным.
5. Замена контроллера — опытный.

**Д11.5. Что уже знаем.** №10 01.11: «тик» и стоп, дисплей не мигал, при толкании карта
дисплей показывал скорость (контроллер жив, датчики Холла читаются). 02.11 владелец
поменял колесо, контроллер и плату — не поехал **[владелец]**. Причина не найдена.

### Д12. Бьётся током

Ссылки: `ai/01-bezopasnost.md` 1.4 и 9, замер И16.

**Д12.1. Сразу — стоп-кран.** Руки от карта. Выдернуть зарядку карта и USB ноутбука,
выключить главный выключатель, отключить батарею разъёмом, если можно взяться за
пластик. Позвать опытного. Карт к гостям не выпускать.

**Д12.2. Расспросить, ничего не трогая.** К чему прикоснулся (рама, сиденье, руль,
колесо, плата)? Руки мокрые? Была ли подключена зарядка карта? Ноутбук на сетевой
зарядке? Одиночный щелчок или постоянное покалывание? После какой работы?

**Д12.3. Зарядка или ноутбук от сети были подключены** — вероятнее всего утечка от
сетевого блока питания **[не проверено: типовое]**. Во время работы их больше не
подключать; зарядку проверяет опытный.

**Д12.4. Одиночный щелчок в сухом воздухе, не повторяется** — статика **[не проверено:
типовое]**. Всё равно пройти Д12.5.

**Д12.5. Осмотр при отключённой батарее.** Голые концы проводов (жёлто-зелёный `J1`,
провод питания педали), перетёртая изоляция там, где провода касаются рамы, особенно
толстые провода, оплавленные места.

**Д12.6. Замер И16** (рама — плюс, рама — минус, при отключённой батарее). Между рамой и
плюсом единицы или десятки Ом → плюс касается рамы, риск пожара: стоп-кран.

**Д12.7. Горячий `F2` или другой элемент платы** одновременно с «кусанием» (как на №10
02.11) — плата неисправна, не включать.

**Д12.8.** Замеры под напряжением (рама относительно полюсов батареи, переменное
напряжение при подключённой зарядке) — только опытный.
